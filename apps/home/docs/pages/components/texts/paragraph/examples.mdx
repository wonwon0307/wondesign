# Examples

This page explains what each prop of `Paragraph` does. Each example shows the
rendered result, followed by its code.

---

## Appearance

Pick the font size with `size`, and the color with `tone`.

### Sizes

The `size` property sets the font size. It's `"medium"` by default:

<Preview orientation="vertical">
  <Paragraph size="large">
    {"Large, for an introduction or long-form reading."}
  </Paragraph>
  <Paragraph size="medium">
    {"Medium, for the body text of most pages."}
  </Paragraph>
  <Paragraph size="small">
    {"Small, for dense layouts, like a card or a sidebar."}
  </Paragraph>
</Preview>

```tsx
<Paragraph size="large">Large, for an introduction or long-form reading.</Paragraph>
<Paragraph size="medium">Medium, for the body text of most pages.</Paragraph>
<Paragraph size="small">
  Small, for dense layouts, like a card or a sidebar.
</Paragraph>
```

### Tones

The `tone` property sets the color. Without it, the paragraph uses
`"default"`, the normal text color, while `"muted"` uses a lighter color:

<Preview orientation="vertical">
  <Heading level={3}>{"Release Notes"}</Heading>
  <Paragraph>
    {
      "This release adds dark mode to every page, and makes search up to twice as fast on large projects."
    }
  </Paragraph>
  <Heading level={3}>{"No Projects Yet"}</Heading>
  <Paragraph tone="muted">
    {"Projects you create or are invited to will show up here."}
  </Paragraph>
</Preview>

```tsx
<Heading level={3}>Release Notes</Heading>
<Paragraph>
  This release adds dark mode to every page, and makes search up to twice as
  fast on large projects.
</Paragraph>

<Heading level={3}>No Projects Yet</Heading>
<Paragraph tone="muted">
  Projects you create or are invited to will show up here.
</Paragraph>
```

## Element

Pass `as` to render the element that fits where it's used. It renders a
`<p>` by default, and the other options are `"div"` and `"span"`:

<Preview orientation="vertical">
  <ul style={{ paddingLeft: "var(--spacing-lg)", listStyle: "disc" }}>
    <li>
      <Paragraph as="span">
        {"Invoices are sent on the 1st of each month."}
      </Paragraph>
    </li>
    <li>
      <Paragraph as="span">
        {"Receipts are emailed after each payment."}
      </Paragraph>
    </li>
  </ul>
</Preview>

```tsx
<ul>
  <li>
    <Paragraph as="span">Invoices are sent on the 1st of each month.</Paragraph>
  </li>
  <li>
    <Paragraph as="span">Receipts are emailed after each payment.</Paragraph>
  </li>
</ul>
```

## Line Clamping

A paragraph shows every line by default. Pass `maxNumLines` to cut it off
after that many lines, with an ellipsis. The cut-off text is still on the
page, so **screen readers read the whole paragraph**, even though it isn't
shown on screen:

<Preview orientation="vertical">
  <Paragraph>
    {
      "A long paragraph that's never cut off, because that's the default, so it wraps onto as many lines as it needs to show every single word, however long it gets. It keeps going onto a third line, and then a fourth, so you can see that nothing is hidden, from the first word right through to the very last one."
    }
  </Paragraph>
  <Paragraph maxNumLines={1}>
    {
      "A long paragraph that's cut off after one line, even if there's more text left to show after it, like the rest of this sentence and everything that comes after it."
    }
  </Paragraph>
  <Paragraph maxNumLines={2}>
    {
      "A long paragraph that's allowed to wrap onto a second line, but is cut off there, even if there's more text left to show after it, like the rest of this sentence and everything that comes after it, and then some more on top of that."
    }
  </Paragraph>
</Preview>

```tsx
// never cut off, the default
<Paragraph>A long paragraph…</Paragraph>

// cut off after one line
<Paragraph maxNumLines={1}>A long paragraph…</Paragraph>

// cut off after two lines
<Paragraph maxNumLines={2}>A long paragraph…</Paragraph>
```

- 📌 A long word or URL is broken onto the next line, instead of running past
  the edge.
- 📌 While clamped, setting `display`, `overflow`, `text-overflow` or
  `-webkit-box-orient` yourself **would break the clamping without an
  error**.
