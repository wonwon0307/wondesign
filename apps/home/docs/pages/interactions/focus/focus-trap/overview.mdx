# Focus Trap

`useFocusTrap` keeps <Keyboard>Tab</Keyboard> and
{<KeyboardGroup shortkey="Shift+Tab" />} inside an element while it's open. Modal
content, like dialogs and alerts, needs it so keyboard users don't wander off to
the page behind.

```tsx
import { useFocusTrap } from "@wondesign/focus/trap";
// or
import { useFocusTrap } from "@wondesign/ui/focus";
```

---

## Key Features

- ✅ **Tab Stays Inside**: Focus wraps from the last element to the first, and back
- ✅ **Skips What Can't Be Focused**: Disabled, hidden and inert elements are left out
- ✅ **Recovers Lost Focus**: When the focused element is removed, the next <Keyboard>Tab</Keyboard> brings focus back inside
- ✅ **Leaves Other Traps Alone**: Focus held by something else isn't pulled back

---

## API

Import `useFocusTrap` and `UseFocusTrapOptions` from `@wondesign/focus/trap`.
`targetRef` is required. The hook returns nothing — it only holds focus:

```ts
function useFocusTrap(
  // the element to keep focus inside.
  targetRef: React.RefObject<HTMLElement | null>,
  options?: UseFocusTrapOptions,
): void;
```

`options` and everything in it can be left out:

```ts
interface UseFocusTrapOptions {
  // whether the trap is on. defaults to `false`.
  // pass the open state, so it only holds focus while open.
  enabled?: boolean;
}
```

---

## Known Issues

- 🐞 **Positive `tabIndex` values**: Elements with `tabIndex={1}` or higher
  inside the trap can be skipped or reached out of order.
- 🐞 **Removing the focused element**: Until the next {<Keyboard>Tab</Keyboard>},
  focus stays on the page, so screen readers announce nothing and keys handled
  inside the element don't reach it.
