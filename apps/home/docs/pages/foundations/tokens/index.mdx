<PackageInfo name="@wondesign/tokens" relPath="foundations/tokens">
  `@wondesign/tokens` is a token foundation for design systems. It defines a
  fixed, semantic vocabulary (`primary`, `spacing.md`, `radius.lg`, …), exposes
  every token as a CSS variable with a built-in fallback, and turns your own
  values into a stylesheet. Just typed objects and plain strings — no
  dependencies, no React.
</PackageInfo>

---

## Installation

```bash
pnpm add @wondesign/tokens
```

With [All-in-One](/all-in-one), import from `@wondesign/ui/tokens` instead.

The tokens rely on `light-dark()`, `color-mix()` and range media queries
(`width >= 768px`), which need modern browsers like Chrome / Edge 123+,
Firefox 120+ or Safari 17.5+. In older browsers, colors, tints and responsive styles may not apply at
all.

## Key Features

- ✅ **Semantic Vocabulary**: Tokens are named by role, not by value, across seven categories
- ✅ **Safe Fallbacks**: Every token falls back to its default value
- ✅ **Light and Dark**: Colors follow the page's color scheme
- ✅ **Build Your Own**: Turn your own values into a stylesheet
- ✅ **Extendable**: Add tokens of your own to any category
- ✅ **Media Queries**: Ready-made breakpoint, hover and reduced motion queries
- ✅ **Framework Agnostic**: Plain strings, for any framework and any way of writing styles

---

## How It Works

A stylesheet, like the WonDesign preset, defines your values as CSS variables.
Every token reads from one of them, and the `tokens` object holds the same
variables as strings, for styles written in JavaScript:

```ts
import { tokens } from "@wondesign/tokens";

tokens.spacing.md; // "var(--spacing-md, 8px)"
```

Each token also has its default value built in as a fallback, so **without a
stylesheet, every token still works**, at its default.

## Known Issues

- 🐞 **colorWithFade in NextJS**: Colors made with `colorWithFade` may not show, or fall back to an unexpected color, when your build tool rewrites `light-dark()` for older browsers. See [Quick Start](/foundations/tokens/quick-start#colors) for the fix
