import { Keyboard } from "@wondesign/ui/code";

# Usage

Turn the hook on with `enabled`. Pass `true` for a group that's always there,
or the open state for one inside a menu or popover. While it's on, the arrow
keys move focus between the items, but don't select them.

---

## Moving Between Items

Pass the container and a selector for its items.
{<Keyboard>←</Keyboard>} and <Keyboard>→</Keyboard> move to the previous and
next item, and <Keyboard>Home</Keyboard> and <Keyboard>End</Keyboard> jump to
the first and last item:

```tsx
import { useRef, useState } from "react";
import { useArrowNavigation } from "@wondesign/focus/arrow-navigation";

const tools = ["Bold", "Italic", "Underline"];

export function Toolbar() {
  const [current, setCurrent] = useState("Bold");
  const toolbarRef = useRef<HTMLDivElement>(null);

  useArrowNavigation(toolbarRef, { itemSelector: "button", enabled: true });

  return (
    <div ref={toolbarRef} role="toolbar" aria-label="Text formatting">
      {tools.map((tool) => (
        <button
          key={tool}
          tabIndex={tool === current ? 0 : -1}
          onFocus={() => setCurrent(tool)}
        >
          {tool}
        </button>
      ))}
    </div>
  );
}
```

---

## Choosing the Items

`itemSelector` is a CSS selector for the items, matched inside the container.
Leave disabled items out of the selector to skip them:

```tsx
useArrowNavigation(tabListRef, {
  itemSelector: '[role="tab"]:not([aria-disabled="true"])',
  enabled: true,
});
```

The arrow keys only work while focus is on one of the items, and move only
between them. Items are looked up on every key press, so items added, removed
or disabled while the hook is on are picked up.

---

## Orientation

Pass `orientation: "vertical"` for a group laid out top to bottom:

```tsx
useArrowNavigation(menuRef, {
  itemSelector: '[role="menuitem"]',
  enabled: isOpen,
  orientation: "vertical",
});
```

{<Keyboard>↑</Keyboard>} and <Keyboard>↓</Keyboard> then move between items
instead. <Keyboard>Home</Keyboard> and <Keyboard>End</Keyboard> work in both
directions.

---

## Looping

Pass `loop` to wrap around at the ends:

```tsx
useArrowNavigation(toolbarRef, {
  itemSelector: "button",
  enabled: true,
  loop: true,
});
```

Without it, focus stops at the first and last item.

---

## Watch Out

- ⚠️ **Make the group a single Tab stop**: Users expect a group to work like
  one control. <Keyboard>Tab</Keyboard> moves into the group, the arrow keys
  move inside it, and the next <Keyboard>Tab</Keyboard> moves out.
  `useArrowNavigation` only handles the arrow keys, so
  **<Keyboard>Tab</Keyboard> still visits every item** unless you set this up:

  - 🔹 Give one item `tabIndex={0}`, so <Keyboard>Tab</Keyboard> lands on it.
  - 🔹 Give every other item `tabIndex={-1}`, so <Keyboard>Tab</Keyboard>
    skips them.
  - 🔹 Move the `0` to whichever item gets focus, so <Keyboard>Tab</Keyboard>
    brings the user back to where they left off. The
    [example](#moving-between-items) does this in `onFocus`.

- ⚠️ **Pass the open state to `enabled`**: With `enabled` always `true`, the
  hook turns on before a container that's rendered conditionally appears, and
  **never picks it up**:

  ```tsx
  // ❌ the hook is already on when the menu appears, so it never sees it
  useArrowNavigation(menuRef, {
    itemSelector: '[role="menuitem"]',
    enabled: true,
  });

  // ✅ the hook turns on together with the menu
  useArrowNavigation(menuRef, {
    itemSelector: '[role="menuitem"]',
    enabled: isOpen,
  });

  return isOpen ? (
    <div ref={menuRef} role="menu">
      …
    </div>
  ) : null;
  ```
