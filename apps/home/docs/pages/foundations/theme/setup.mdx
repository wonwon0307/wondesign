# Setup

Setting up the theme takes three pieces, all at the root of your app:

- 🔵 **Provider** — `LightDarkProvider` or `ThemeProvider`. The React context
  that the hook reads, and that keeps `<html>` in sync when the theme changes.
- 🔵 **Script** — `LightDarkScript` or `ThemeScript`. An inline script in the
  `<head>` that applies the saved theme before the first paint.
- 🔵 **CSS** — your colors, built with `light-dark()` or keyed on `data-theme` /
  `data-color-scheme`.

---

## Configuration

There are three ways to configure the theme. Pick one per app.

### Light-Dark

A light / dark / system switch, and the simplest setup. Colors from the
[`@wondesign/tokens` preset](/foundations/tokens/quick-start) already follow it.
Otherwise, write your own with CSS's
[`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark).

For this method, **do not pass anything to the `themes` property**.

```tsx
import { LightDarkProvider } from "@wondesign/theme/light-dark";
import { LightDarkScript } from "@wondesign/theme/light-dark/server";

<LightDarkScript />
<LightDarkProvider>{children}</LightDarkProvider>
```

```css
/* light-dark(<light value>, <dark value>) */
body {
  background: light-dark(#ffffff, #1c1c1e);
  color: light-dark(#1c1c1e, #f5f5f7);
}
```

Pass `disableSystem` to remove `"system"`, so the OS setting is never
consulted. Without a default mode, first-time visitors then get light mode
instead of following their OS:

```tsx
<LightDarkProvider disableSystem>{children}</LightDarkProvider>
```

### Advanced Light-Dark

Light-Dark with more than one theme per side. The user picks light, dark or
system, and a theme for each side. Style the extra themes with `data-theme`
selectors.

Pass `themes` to both. The first theme of each side is its default:

```tsx
const themes = {
  light: ["light", "paper"], // first item "light" is the default
  dark: ["dark", "midnight"], // first item "dark" is the default
} as const;

<LightDarkScript themes={themes} />
<LightDarkProvider themes={themes}>{children}</LightDarkProvider>
```

`disableSystem` works here too, the same as in [Light-Dark](#light-dark).
See the [NextJS example](#nextjs-app-router) for the CSS.

### Named Themes

A flat list of themes, none tied to light or dark. Style each with
`data-theme` selectors.

Pass your theme names to `ThemeProvider`, and the default to both. If you
leave `defaultTheme` out of the provider, the first theme is the default:

```tsx
import { ThemeProvider } from "@wondesign/theme";
import { ThemeScript } from "@wondesign/theme/server";

const themes = ["ocean", "forest", "sunset"] as const;

<ThemeScript defaultTheme="ocean" />
<ThemeProvider themes={themes} defaultTheme="ocean">{children}</ThemeProvider>
```

See the [client-only example](#client-only-apps) for the CSS.

## Notes

A few things to keep in mind, whichever configuration you choose.

### Matching options

<Callout title="Mismatched options cause a flash" variant="warning">
  Both resolve the theme on their own, and if their options differ, the page
  might flash from one theme to the other on load.
</Callout>

Any option you leave out falls back to the same default on both.

**Light-Dark**

Pass the same themes, default mode, and storage key to both. The script doesn't
know about `disableSystem`, and it defaults to system mode. **If you disable
system mode, give the script your default mode as well.**

```tsx
<LightDarkScript themes={themes} defaultMode="dark" />
<LightDarkProvider themes={themes} defaultMode="dark">{children}</LightDarkProvider>
```

**Named Themes**

Pass the same default theme and storage key to both. The script doesn't get
the list of themes, so a user whose theme you removed may see it briefly on
their next visit.

```tsx
<ThemeScript defaultTheme="ocean" />
<ThemeProvider themes={themes} defaultTheme="ocean">{children}</ThemeProvider>
```

### Unique theme names

Every theme name should be unique — a duplicate warns in the console. With
Light-Dark, that's across both sides. Each of the following triggers a
warning:

```ts
// for Light-Dark
const duplicateWithin = { light: ["light", "light"], dark: ["dark"] };
const duplicateAcross = {
  light: ["light", "colorful"],
  dark: ["dark", "colorful"],
};

// for Named
const duplicateNamed = ["ocean", "forest", "ocean"];
```

### Content Security Policy

Both scripts are inline. If your Content-Security-Policy only allows inline
scripts that carry a nonce, the browser blocks them, and the page falls back
to the flash. **Pass the nonce your server generated for the request:**

```tsx
<LightDarkScript nonce={nonce} />
<ThemeScript defaultTheme="ocean" nonce={nonce} />
```

The nonce has to be generated per request, so the page can't be statically
rendered.

## Examples

Where the provider and the script go depends on your framework.

### NextJS (App Router)

An Advanced Light-Dark setup, with two themes per side:

```tsx
// app/layout.tsx
import { LightDarkProvider } from "@wondesign/theme/light-dark";
import { LightDarkScript } from "@wondesign/theme/light-dark/server";
import "./globals.css";

const themes = {
  light: ["light", "paper"],
  dark: ["dark", "midnight"],
} as const;

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        {/* With a nonce-based CSP, also pass nonce={nonce} — see Content Security Policy */}
        <LightDarkScript themes={themes} />
      </head>
      <body>
        <LightDarkProvider themes={themes}>{children}</LightDarkProvider>
      </body>
    </html>
  );
}
```

`"light"` and `"dark"` use the `light-dark()` colors, and `"paper"` and
`"midnight"` override them with `data-theme`:

```css
/* app/globals.css */
:root {
  --background: light-dark(#ffffff, #1c1c1e);
  --text: light-dark(#1c1c1e, #f5f5f7);
}

[data-theme="paper"] {
  --background: #f7f1e3;
  --text: #3b3024;
}

[data-theme="midnight"] {
  --background: #0a0f1f;
  --text: #dbe4ff;
}

body {
  background: var(--background);
  color: var(--text);
}
```

The script sets attributes on `<html>` before React hydrates, so
**`suppressHydrationWarning` on `<html>` is required**, or React logs a
hydration mismatch. Both providers are client components, so a server layout
can render them.

**light-dark() colors**: NextJS rewrites `light-dark()` for older browsers,
and the rewritten colors only follow a `color-scheme` declared in your CSS,
not the one the provider sets. **Without one, they ignore the theme.**
Declare it on the root:

```css
/* app/globals.css */
:root {
  color-scheme: light dark;
}

:root[data-color-scheme="light"] {
  color-scheme: light;
}

:root[data-color-scheme="dark"] {
  color-scheme: dark;
}
```

The first rule follows the OS until a theme is applied, and the other two
follow the user's choice. Or, if your app only supports browsers with
`light-dark()`, set `browserslist` in your `package.json`, so NextJS leaves it
as is:

```json
{
  "browserslist": [
    "chrome >= 123",
    "edge >= 123",
    "firefox >= 120",
    "safari >= 17.5"
  ]
}
```

### React Router (Framework Mode)

A simple Light-Dark setup. Render the script in the root `Layout`, before
`<Meta />` and `<Links />`:

```tsx
// app/root.tsx
import { Links, Meta, Outlet, Scripts, ScrollRestoration } from "react-router";
import { LightDarkProvider } from "@wondesign/theme/light-dark";
import { LightDarkScript } from "@wondesign/theme/light-dark/server";
import "./app.css";

export function Layout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <meta charSet="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <LightDarkScript />
        <Meta />
        <Links />
      </head>
      <body>
        <LightDarkProvider>{children}</LightDarkProvider>
        <ScrollRestoration />
        <Scripts />
      </body>
    </html>
  );
}

export default function App() {
  return <Outlet />;
}
```

```css
/* app/app.css */
body {
  background: light-dark(#ffffff, #1c1c1e);
  color: light-dark(#1c1c1e, #f5f5f7);
}
```

As with NextJS, **`suppressHydrationWarning` on `<html>` is required.**

### Client-only Apps

Client-only apps (Vite, Rsbuild, Parcel, etc.) have no server to render the
script. Render it once at build time, into the `<head>` of your `index.html`.
A Named Themes setup with Vite:

```ts
// vite.config.ts
import { createElement } from "react";
import { renderToStaticMarkup } from "react-dom/server";
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { ThemeScript } from "@wondesign/theme/server";

const themeScript = renderToStaticMarkup(
  createElement(ThemeScript, { defaultTheme: "ocean" }),
);

export default defineConfig({
  plugins: [
    react(),
    {
      name: "theme-script",
      transformIndexHtml: (html) =>
        html.replace("<head>", `<head>${themeScript}`),
    },
  ],
});
```

Then render the provider at the root, as usual:

```tsx
// main.tsx
import { createRoot } from "react-dom/client";
import { ThemeProvider } from "@wondesign/theme";
import "./index.css";

createRoot(document.getElementById("root")!).render(
  <ThemeProvider themes={["ocean", "forest", "sunset"]} defaultTheme="ocean">
    <App />
  </ThemeProvider>,
);
```

```css
/* index.css */
[data-theme="ocean"] {
  --background: #f0f7ff;
  --text: #0b2545;
}

[data-theme="forest"] {
  --background: #f1f7ee;
  --text: #1b3a1a;
}

[data-theme="sunset"] {
  --background: #fff4ec;
  --text: #4a1c0c;
}

body {
  background: var(--background);
  color: var(--text);
}
```

Since the script is baked into a static file, it can't carry a per-request
nonce. With a nonce-based CSP, allow it by its hash instead.
