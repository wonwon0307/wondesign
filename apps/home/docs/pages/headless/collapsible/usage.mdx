# Usage

This page covers how to control, extend and style `Collapsible`. For what
each prop does, refer to the [API tab](/headless/collapsible/api).

---

## Open State

`Collapsible` keeps its own state and starts closed. Pass `defaultOpen` to
start it open, or `isOpen` and `onOpenChange` to control it yourself. Both
modes are powered by
[Disclosure](/interactions/disclosure/open-state/usage), so they behave
exactly as described there:

```tsx
// uncontrolled, starts closed
<Collapsible>…</Collapsible>;

// uncontrolled, starts open
<Collapsible defaultOpen>…</Collapsible>;

// controlled
const [open, setOpen] = useState(false);

<Collapsible isOpen={open} onOpenChange={setOpen}>
  …
</Collapsible>;
```

---

## Running an Action

Pass `onClick` to `Collapsible.Toggle` to run an action. It runs your
`onClick` first, then opens or closes the content, so you don't need to toggle
it yourself. To skip the toggle in certain cases, call
`event.preventDefault()`:

```tsx
const handleToggle = (event) => {
  if (hasUnsavedChanges) {
    event.preventDefault(); // keeps the content open
    return;
  }
  trackToggle();
};

<Collapsible.Toggle onClick={handleToggle}>Edit details</Collapsible.Toggle>;
```

For full control, call `event.preventDefault()` every time, and open or close
the content yourself with `toggle` from [`useCollapsible`](#custom-parts).

## Custom Parts

`useCollapsible` gives any component inside a `Collapsible` its open state and
a `toggle` function:

```tsx
import { useCollapsible } from "@wondesign/headless/Collapsible";

function Chevron() {
  const { isOpen } = useCollapsible();

  return <ChevronIcon className={isOpen ? "rotated" : undefined} />;
}
```

A common use is a close button inside the content, like a "Hide details"
button at the end of a long section. Build it with `toggle`, not
`Collapsible.Toggle`:

```tsx
function HideButton() {
  const { toggle } = useCollapsible();

  return (
    <button type="button" onClick={toggle}>
      {"Hide details"}
    </button>
  );
}
```

## Your Own Elements

`Collapsible.Toggle` and `Collapsible.Content` take `asChild`, which renders
your own element or component instead, like a styled button for the toggle,
or a `<section>` for the content:

```tsx
import { Button } from "@wondesign/buttons/Button";

<Collapsible>
  <Collapsible.Toggle asChild>
    <Button>Show details</Button>
  </Collapsible.Toggle>
  <Collapsible.Content asChild>
    <section>…</section>
  </Collapsible.Content>
</Collapsible>;
```

With `asChild`, the content **has no role** unless you pass one. For how props
and refs are merged, refer to [AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/collapsible/api), so you can
style each state without extra props:

```css
.toggle[data-state="open"] { … }
.content[data-state="open"] { … }
```

### Exit Animations

Animate the content with CSS, using its `data-state`. When it closes, it
stays on the page until its animations and transitions finish:

```css
.content[data-state="open"] {
  animation: fade-in 200ms;
}

.content[data-state="closed"] {
  animation: fade-out 200ms;
}
```

While it's leaving, it can't be clicked or focused, and screen readers treat
it as closed. **Animations that repeat forever aren't waited for.**
