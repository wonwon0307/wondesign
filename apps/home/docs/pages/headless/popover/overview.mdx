# Popover

`Popover` shows floating content next to its trigger, as a non-modal dialog,
following the
[WAI-ARIA Dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
without the parts that make it modal (focus trap, background inert and scroll
lock). It handles opening and closing, moves
focus in and back out, works out where the content fits on screen, and labels
it for assistive technology, so you only bring the look.

Use it when the content belongs next to its trigger, like a filter form or
quick settings. The page behind **stays usable** while it's open. For a long
form or a step the user has to finish before carrying on, use a
[Modal](/headless/modal) instead. For a short hint with nothing to interact
with, use a [Tooltip](/headless/tooltip) instead.

```tsx
import { Popover } from "@wondesign/headless/Popover";
// or
import { Popover } from "@wondesign/ui/headless";
```

---

## Key Features

- ✅ **Accessible by Default**: Announced as a dialog, named by its title
- ✅ **Easy to Dismiss**: Closes with a close button, a click outside, or <Keyboard>Esc</Keyboard> while focus is inside it
- ✅ **Focus Management**: Moves focus in when it opens, and returns it to the trigger when it closes
- ✅ **Non-Modal**: Focus isn't trapped, and the page behind stays usable while it's open
- ✅ **Computed Position**: Works out where it fits next to the trigger, and stays inside the viewport
- ✅ **Controlled & Uncontrolled**: Let it manage the open state, or drive it yourself
- ✅ **Keep Content Mounted**: Hide closed content instead of removing it
- ✅ **Exit Animations**: Closed content stays until its exit animation finishes
- ✅ **Composable**: Render your own elements with [`asChild`](/headless/as-child)

## Structure

For how to control, extend and style it, refer to the
[Usage tab](/headless/popover/usage). For what each prop does, refer to the
[API tab](/headless/popover/api).

- 🧩 **Popover**: holds the open state, handles focus and works out the position
- 🧩 **Popover.Trigger**: the button that opens and closes the popover
- 🧩 **Popover.Content**: the floating dialog itself
- 🧩 **Popover.Title**: the heading that names the popover
- 🧩 **Popover.Close**: a button that closes the popover
- 🧩 **Popover.Arrow**: an optional arrow pointing at the trigger

```tsx
// compound component, with its parts attached
<Popover>
  <Popover.Trigger>Filters</Popover.Trigger>
  <Popover.Content>
    <Popover.Title>Filters</Popover.Title>
    {/* … */}
    <Popover.Close>Done</Popover.Close>
    <Popover.Arrow>…</Popover.Arrow>
  </Popover.Content>
</Popover>;

// or, with named exports
<PopoverProvider>
  <PopoverTrigger>Filters</PopoverTrigger>
  <PopoverContent>
    <PopoverTitle>Filters</PopoverTitle>
    {/* … */}
    <PopoverClose>Done</PopoverClose>
    <PopoverArrow>…</PopoverArrow>
  </PopoverContent>
</PopoverProvider>;
```

## Known Issues

- 🐞 **Nested overlays close the popover**: Clicking inside a popover, tooltip
  or other overlay opened from inside the popover counts as a click outside,
  and closes it.
- 🐞 **Tab leaves the content in page order**: <Keyboard>Tab</Keyboard> past
  its last element when the content is rendered at the end of the DOM tree
  (for example in a [Portal](/headless/portal)) moves the focus to the browser's
  address bar, and {<KeyboardGroup shortkey="Shift+Tab" />} before its first
  element moves to the last element on the page, instead of next to the trigger.

---

## Watch Out

- ⚠️ **Use named exports in Server Components**: The parts are client
  components, so a Server Component **can't reach `Popover.Trigger` through
  `Popover`**. Import `PopoverTrigger` and the other parts on their own instead.
- ⚠️ **Closed content can stay visible**: With `keepMounted`, a `display`
  value in your styles overrides the `hidden` attribute, so **it stays
  visible** with no error. Set the `display` only while it's open, with
  `[data-state="open"]`.
- ⚠️ **Content can end up somewhere unexpected**: With `disablePortal`, inside
  an ancestor with a `transform`, `filter` or similar, `position: fixed` is
  measured from that ancestor instead of the viewport, so **the content could
  be placed somewhere unexpected** with no error.
