# Usage

This page covers how to control, extend and style `Popover`. For what each
prop does, refer to the [API tab](/headless/popover/api).

---

## Applying the Position

`Popover` works out where the content and arrow go, but **doesn't move them
there**. Unless you calculate the position on your own, apply the positions
from `usePopover` yourself, usually in a small wrapper of your own.

`content` is measured from the top left of the viewport, so use `position: fixed`.

`arrow` is measured from the top left of the content, so use `position: absolute`.

```tsx
import { Popover, usePopover } from "@wondesign/headless/Popover";

function MyPopoverContent({ children }: { children: React.ReactNode }) {
  const { content, isPositioned } = usePopover();

  return (
    <Popover.Content
      style={{
        position: "fixed",
        top: 0,
        left: 0,
        transform: `translate3d(${content.x}px, ${content.y}px, 0)`,
        visibility: isPositioned ? "visible" : "hidden",
      }}
    >
      {children}
    </Popover.Content>
  );
}
```

For more details, refer to
[Floating Position](/interactions/position/floating-position/usage).

### Updating the Position

The position updates on its own when the page scrolls or resizes, or when the
trigger or content changes size. When the trigger moves for another reason,
call `updatePosition`:

```tsx
const { updatePosition } = usePopover();

useEffect(updatePosition, [layoutChanged, updatePosition]);
```

## Open State

`Popover` keeps its own state and starts closed. Pass `defaultOpen` to start it
open, or `isOpen` and `onOpenChange` to control it yourself. Both modes are
powered by [Disclosure](/interactions/disclosure/open-state/usage), so
they behave exactly as described there:

```tsx
// uncontrolled, starts closed
<Popover>…</Popover>;

// uncontrolled, starts open
<Popover defaultOpen>…</Popover>;

// controlled
const [open, setOpen] = useState(false);

<Popover isOpen={open} onOpenChange={setOpen}>
  …
</Popover>;
```

## Running an Action

Pass `onClick` to `Popover.Trigger` or `Popover.Close` to run an action. It
runs your `onClick` first, then opens or closes the popover, so you don't need
to do it yourself. To skip that in certain cases, call
`event.preventDefault()`:

```tsx
const handleShare = (event) => {
  if (!isSignedIn) {
    event.preventDefault(); // keeps the popover closed
    redirectToSignIn();
  }
};

const handleSend = (event) => {
  if (!hasRecipient) {
    event.preventDefault(); // keeps the popover open
    return;
  }
  sendInvite();
};

<Popover>
  <Popover.Trigger onClick={handleShare}>Share</Popover.Trigger>
  <Popover.Content>
    {/* … */}
    <Popover.Close>Cancel</Popover.Close>
    <Popover.Close onClick={handleSend}>Send</Popover.Close>
  </Popover.Content>
</Popover>;
```

### Async Actions

The popover closes right after `onClick` runs. **It doesn't wait for a
returned promise**, so a failing action can't keep it open. To keep it open
until an action finishes, call `event.preventDefault()`, show the progress with
`isLoading`, and close the popover yourself with `hidePopover` from
[`usePopover`](#custom-parts):

```tsx
import { Popover, usePopover } from "@wondesign/headless/Popover";

function SaveButtons() {
  const { hidePopover } = usePopover();
  const [isSaving, setSaving] = useState(false);

  const handleSave = async (event: React.MouseEvent) => {
    event.preventDefault(); // keeps the popover open
    setSaving(true);

    try {
      await saveSettings();
      hidePopover();
    } finally {
      setSaving(false);
    }
  };

  return (
    <>
      <Popover.Close isDisabled={isSaving}>Cancel</Popover.Close>
      <Popover.Close isLoading={isSaving} onClick={handleSave}>
        Save
      </Popover.Close>
    </>
  );
}
```

While the action runs, the trigger, a click outside and <Keyboard>Esc</Keyboard>
**can still close the popover**. To block them, control the popover and ignore
closes in `onOpenChange` until the action is done.

### Submitting a Form

`Popover.Close` accepts `type="submit"` (`Popover.Trigger` doesn't), so it
can submit a form inside the
popover and close it in one click. When the form isn't valid, call
`event.preventDefault()` to keep the popover open. This also stops the form
from submitting:

```tsx
const handleSubscribe = (event) => {
  if (!event.currentTarget.form?.reportValidity()) {
    event.preventDefault(); // keeps the popover open
  }
};

<Popover.Content>
  <form onSubmit={subscribe}>
    <input type="email" name="email" required />
    <Popover.Close type="submit" onClick={handleSubscribe}>
      Subscribe
    </Popover.Close>
  </form>
</Popover.Content>;
```

## Focus Management

By default, focus moves to the first focusable element inside the content when
the popover opens, and returns to `Popover.Trigger` when it closes. Pass
`initialFocusRef` to start somewhere else, and `returnFocusRef` to send it
somewhere else on close.

`initialFocusRef` must point inside the content. Outside it,
**it's ignored silently**, and focus moves to the first focusable element instead:

```tsx
const confirmRef = useRef<HTMLButtonElement>(null);
const dateFieldRef = useRef<HTMLInputElement>(null);

<>
  <input ref={dateFieldRef} aria-label="Date" value={selected} readOnly />
  <Popover initialFocusRef={confirmRef} returnFocusRef={dateFieldRef}>
    <Popover.Trigger>Pick a date</Popover.Trigger>
    <Popover.Content>
      <Popover.Title>Dates</Popover.Title>
      {/* … */}
      <Popover.Close ref={confirmRef}>Confirm</Popover.Close>
    </Popover.Content>
  </Popover>
</>;
```

Focus management is handled by [Auto Focus](/interactions/focus/auto-focus/usage),
so it behaves exactly as described there, including when the element can't
take focus.

## Custom Parts

`usePopover` gives any component inside `Popover` the open state, the position,
and ways to open, close or toggle it. For example, a menu item that opens the
popover:

```tsx
import { usePopover } from "@wondesign/headless/Popover";

function EditMenuItem() {
  const { showPopover } = usePopover();

  return (
    <div role="menuitem" onClick={showPopover}>
      Edit
    </div>
  );
}
```

The content is **still positioned against `Popover.Trigger`**, wherever it's
opened from.

## Your Own Elements

Every part except the provider and `Popover.Arrow` takes `asChild`, which
renders your own element or component instead, like another heading level for
the title:

```tsx
<Popover.Title asChild>
  <h3>Filters</h3>
</Popover.Title>
```

For how props and refs are merged, refer to
[AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/popover/api), so you can style
each state without extra props:

```css
.trigger[data-state="open"] { … }
.content[data-state="open"] { … }
.arrow[data-placement="top"] { … }
.close[data-loading] { … }
```

### Exit Animations

Animate the content with CSS, using its `data-state`. When it closes, it stays
on the page until its animations and transitions finish:

```css
.content[data-state="open"] {
  animation: fade-in 200ms;
}

.content[data-state="closed"] {
  animation: fade-out 200ms;
}
```

While it's leaving, it can't be clicked or focused, and screen readers treat
it as closed. **Animations that repeat forever aren't waited for.**
