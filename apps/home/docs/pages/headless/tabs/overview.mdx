# Tabs

`Tabs` shows one panel at a time, chosen from a list of tabs, following the
[WAI-ARIA Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). It
handles selection and keyboard navigation, so you only bring the look.

Use it to split related content into views the user switches between on the
same page, like the sections of a settings page, or a product's description,
specs and reviews. For tabs that navigate between pages, like a row of links
styled as tabs, use [Navbar](/components/navbar) instead.

```tsx
import { Tabs } from "@wondesign/headless/Tabs";
// or
import { Tabs } from "@wondesign/ui/headless";
```

For ready-made styled tabs, use [`@wondesign/tabs`](/components/tabs), which
builds on `Tabs`.

---

## Key Features

- ✅ **Accessible by Default**: Each tab is linked to its panel for assistive technology
- ✅ **Arrow Key Navigation**: Move between tabs with the arrow keys, <Keyboard>Home</Keyboard> and <Keyboard>End</Keyboard>
- ✅ **Single Tab Stop**: <Keyboard>Tab</Keyboard> lands on the selected tab, and the next <Keyboard>Tab</Keyboard> moves into its panel
- ✅ **Controlled & Uncontrolled**: Let it manage the selected tab, or drive it yourself
- ✅ **Horizontal & Vertical**: Arrow keys follow the direction of the list
- ✅ **Disabled Tabs**: Turn off a single tab, or all of them
- ✅ **Keep Panels Mounted**: Hide inactive panels instead of removing them
- ✅ **Exit Animations**: An inactive panel stays until its exit animation finishes
- ✅ **Composable**: Render your own elements with [`asChild`](/headless/as-child)

## Structure

For how to control, extend and style it, refer to the
[Usage tab](/headless/tabs/usage). For what each prop does, refer to the
[API tab](/headless/tabs/api).

- 🧩 **Tabs**: holds the selected tab and links each tab to its panel
- 🧩 **Tabs.List**: the container that groups the tabs
- 🧩 **Tabs.Tab**: a button that selects its panel
- 🧩 **Tabs.Panel**: the content shown for its tab

```tsx
// compound component, with its parts attached
<Tabs defaultTab="account">
  <Tabs.List aria-label="Settings">
    <Tabs.Tab tabName="account">Account</Tabs.Tab>
    <Tabs.Tab tabName="billing">Billing</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel tabName="account">…</Tabs.Panel>
  <Tabs.Panel tabName="billing">…</Tabs.Panel>
</Tabs>;

// or, with named exports
<TabsProvider defaultTab="account">
  <TabsList aria-label="Settings">
    <Tab tabName="account">Account</Tab>
    <Tab tabName="billing">Billing</Tab>
  </TabsList>
  <TabPanel tabName="account">…</TabPanel>
  <TabPanel tabName="billing">…</TabPanel>
</TabsProvider>;
```

---

## Watch Out

- ⚠️ **Use named exports in Server Components**: The parts are client
  components, so a Server Component **can't reach `Tabs.List` through
  `Tabs`**. Import `TabsList` and the other parts on their own instead.
- ⚠️ **Inactive panels can stay visible**: With `keepMounted`, a
  `display` value in your styles overrides the `hidden` attribute, so **they
  stay visible** with no error. Set the `display` only while active, with
  `[data-state="active"]`.
