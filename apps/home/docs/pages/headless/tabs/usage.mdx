# Usage

This page covers how to control, extend and style `Tabs`. For what each prop
does, refer to the [API tab](/headless/tabs/api).

To see real, styled examples of `Tabs`, go to the
[Examples tab](/components/tabs/examples) of `@wondesign/tabs`.

---

## Selected Tab

`Tabs` keeps its own selected tab, and starts on the first enabled tab. Pass
`defaultTab` to choose which one it starts on, or `selectedTab` and
`onTabChange` to control it yourself:

```tsx
// uncontrolled, starts on the first enabled tab
<Tabs>…</Tabs>

// uncontrolled, starts on "billing"
<Tabs defaultTab="billing">…</Tabs>

// controlled
const [tab, setTab] = useState("account");

<Tabs selectedTab={tab} onTabChange={setTab}>…</Tabs>;
```

If no enabled tab matches, **the first enabled tab is selected**, and
`onTabChange` is called with it, even when controlled.

---

## Running an Action

Pass `onClick` to `Tabs.Tab` to run an action. It runs your `onClick` first,
then selects its panel, so you don't need to select it yourself. To keep the
current tab in certain cases, call `event.preventDefault()`:

```tsx
const handleBillingClick = (event) => {
  if (hasUnsavedChanges) {
    event.preventDefault(); // keeps the current tab
    showToast("Save your changes first");
  }
};

<Tabs.Tab tabName="billing" onClick={handleBillingClick}>
  Billing
</Tabs.Tab>;
```

With `switchOnFocus`, a tab is selected as soon as it's focused, before
`onClick` can run. **Leave it off when an action has to run before
switching.**

## Labelling the List

Label the list with an `aria-label`, or `aria-labelledby` pointing to a visible
heading. `Tabs.List` warns in development when it has neither:

```tsx
// labelled by aria-label
<Tabs.List aria-label="Settings">…</Tabs.List>

// labelled by a visible heading
<h2 id="settings-heading">Settings</h2>
<Tabs.List aria-labelledby="settings-heading">…</Tabs.List>
```

If you pass both, `aria-labelledby` is used and **`aria-label` is dropped**.

## Custom Parts

`useTabs` gives any component inside `Tabs` the selected tab, a way to change
it, and whether the tabs are disabled:

```tsx
import { useTabs } from "@wondesign/headless/Tabs";

function NextButton() {
  const { updateActiveTab } = useTabs();

  return <button onClick={() => updateActiveTab("billing")}>Next</button>;
}
```

## Your Own Elements

`Tabs.List`, `Tabs.Tab` and `Tabs.Panel` take `asChild`, which renders your
own element or component instead, like a `<section>` for a panel:

```tsx
<Tabs.Panel tabName="account" asChild>
  <section>…</section>
</Tabs.Panel>
```

For how props and refs are merged, refer to
[AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/tabs/api), so you can style
each state without extra props:

```css
.tab[data-state="active"] { … }
.list[data-orientation="vertical"] { … }
```

### Exit Animations

Animate the panels with CSS, using their `data-state`. When another tab is
selected, the old panel stays on the page until its animations and
transitions finish:

```css
.panel[data-state="active"] {
  animation: fade-in 200ms;
}

.panel[data-state="inactive"] {
  animation: fade-out 200ms;
}
```

While it's leaving, it can't be clicked or focused, and screen readers skip
it. **Animations that repeat forever aren't waited for.**

While the old panel leaves, **both panels are on the page**, so the new one
shows below it until it's gone. Stack the panels in your styles, like in one
grid cell, to animate one over the other.
