# Usage

This page covers how to control, extend and style `Tooltip`. For what each
prop does, refer to the [API tab](/headless/tooltip/api).

To see real, styled examples of `Tooltip`, go to the
[Examples tab](/components/tooltip/examples) of `@wondesign/tooltip`.

---

## Applying the Position

`Tooltip` works out where the content and arrow go, but **doesn't move them
there**. Unless you calculate the position on your own, apply the positions
from `useTooltip` yourself, usually in a small wrapper of your own.

`content` is measured from the top left of the viewport, so use `position: fixed`.

`arrow` is measured from the top left of the content, so use `position: absolute`.

```tsx
import { Tooltip, useTooltip } from "@wondesign/headless/Tooltip";

function MyTooltipContent({ children }: { children: React.ReactNode }) {
  const { content, isPositioned } = useTooltip();

  return (
    <Tooltip.Content
      style={{
        position: "fixed",
        top: 0,
        left: 0,
        transform: `translate3d(${content.x}px, ${content.y}px, 0)`,
        visibility: isPositioned ? "visible" : "hidden",
      }}
    >
      {children}
    </Tooltip.Content>
  );
}
```

For more details, refer to
[Floating Position](/interactions/position/floating-position/usage).

### Updating the Position

The position updates on its own when the page scrolls or resizes, or when the
trigger or content changes size. When the trigger moves for another reason,
call `updatePosition`:

```tsx
const { updatePosition } = useTooltip();

useEffect(updatePosition, [layoutChanged, updatePosition]);
```

## Open State

`Tooltip` keeps its own state and starts closed. Pass `isOpen` and
`onOpenChange` to control it yourself. Both modes are powered by
[Disclosure](/interactions/disclosure/open-state/usage), so they behave
exactly as described there:

```tsx
// uncontrolled, starts closed
<Tooltip>…</Tooltip>;

// controlled
const [open, setOpen] = useState(false);

<Tooltip isOpen={open} onOpenChange={setOpen}>
  …
</Tooltip>;
```

## Custom Parts

`useTooltip` gives any component inside `Tooltip` the open state, the
position, and ways to show or hide it, with or without the delays. For example,
a help icon next to the trigger that opens the same tooltip on hover:

```tsx
import { useTooltip } from "@wondesign/headless/Tooltip";

function HelpIcon() {
  const { showWithDelay, hideWithDelay } = useTooltip();

  return (
    <span aria-hidden onMouseEnter={showWithDelay} onMouseLeave={hideWithDelay}>
      ?
    </span>
  );
}
```

The content is **still positioned against `Tooltip.Trigger`**, wherever it's
opened from.

## Your Own Elements

`Tooltip.Trigger` and `Tooltip.Content` take `asChild`, which renders your own
element or component instead, like an [`Anchor`](/headless/anchor) for the
trigger:

```tsx
import { Anchor } from "@wondesign/headless/Anchor";

<Tooltip>
  <Tooltip.Trigger asChild>
    {/* give icon-only triggers a label, since the tooltip only describes them */}
    <Anchor href="https://github.com/wonwon0307" aria-label="GitHub">
      <GithubLogo />
    </Anchor>
  </Tooltip.Trigger>
  <Tooltip.Content>Visit my GitHub</Tooltip.Content>
</Tooltip>;
```

For how props and refs are merged, refer to
[AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/tooltip/api), so you can style
each state without extra props:

```css
.trigger[data-state="open"] { … }
.content[data-state="open"] { … }
.arrow[data-placement="top"] { … }
```

### Exit Animations

Animate the content with CSS, using its `data-state`. When it hides, it stays
on the page until its animations and transitions finish:

```css
.content[data-state="open"] {
  animation: fade-in 150ms;
}

.content[data-state="closed"] {
  animation: fade-out 150ms;
}
```

While it's leaving, it can't be hovered or clicked, and screen readers treat
it as closed. **Animations that repeat forever aren't waited for.**
