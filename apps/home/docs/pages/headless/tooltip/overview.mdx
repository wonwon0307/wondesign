# Tooltip

`Tooltip` shows short floating content for its trigger, following the
[WAI-ARIA Tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/).
It handles when to show and hide it, works out where it fits on screen, and
links it to the trigger for assistive technology, so you only bring the look.

Use it for a short hint about its trigger, like the name of an icon-only
button or a keyboard shortcut. It can also explain why a button is disabled.
For content with links or buttons, use a [Popover](/headless/popover)
instead.

```tsx
import { Tooltip } from "@wondesign/headless/Tooltip";
// or
import { Tooltip } from "@wondesign/ui/headless";
```

For a ready-made styled tooltip, use [`@wondesign/tooltip`](/components/tooltip),
which builds on `Tooltip`.

---

## Key Features

- ✅ **Accessible by Default**: The tooltip describes its trigger for assistive technology
- ✅ **Hover, Focus & Long Press**: Shows while the trigger is hovered or focused, or after a long press
- ✅ **Easy to Dismiss**: Hides on <Keyboard>Esc</Keyboard> or a click outside
- ✅ **Computed Position**: Works out where it fits next to the trigger, and stays inside the viewport
- ✅ **Show & Hide Delays**: Tune how quickly it reacts to the pointer
- ✅ **Controlled & Uncontrolled**: Let it manage the open state, or drive it yourself
- ✅ **Keep Content Mounted**: Hide closed content instead of removing it
- ✅ **Exit Animations**: Closed content stays until its exit animation finishes
- ✅ **Composable**: Render your own elements with [`asChild`](/headless/as-child)

## Structure

For how to control, extend and style it, refer to the
[Usage tab](/headless/tooltip/usage). For what each prop does, refer to the
[API tab](/headless/tooltip/api).

- 🧩 **Tooltip**: holds the open state and works out the position
- 🧩 **Tooltip.Trigger**: the button the tooltip describes
- 🧩 **Tooltip.Content**: the floating body of the tooltip
- 🧩 **Tooltip.Arrow**: an optional arrow pointing at the trigger

```tsx
// compound component, with its parts attached
<Tooltip>
  <Tooltip.Trigger>Save</Tooltip.Trigger>
  <Tooltip.Content>
    Save your changes
    <Tooltip.Arrow>…</Tooltip.Arrow>
  </Tooltip.Content>
</Tooltip>;

// or, with named exports
<TooltipProvider>
  <TooltipTrigger>Save</TooltipTrigger>
  <TooltipContent>
    Save your changes
    <TooltipArrow>…</TooltipArrow>
  </TooltipContent>
</TooltipProvider>;
```

---

## Watch Out

- ⚠️ **Use named exports in Server Components**: The parts are client
  components, so a Server Component **can't reach `Tooltip.Trigger` through
  `Tooltip`**. Import `TooltipTrigger` and the other parts on their own instead.
- ⚠️ **Closed content can stay visible**: With `keepMounted`, a `display`
  value in your styles overrides the `hidden` attribute, so **it stays
  visible** with no error. Set the `display` only while it's open, with
  `[data-state="open"]`.
- ⚠️ **Content can end up somewhere unexpected**: With `disablePortal`, inside
  an ancestor with a `transform`, `filter` or similar, `position: fixed` is
  measured from that ancestor instead of the viewport, so **the content could be
  placed somewhere unexpected** with no error.
