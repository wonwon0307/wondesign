# Toast

`Toast` shows a short message without interrupting the user, as a
[WCAG status message](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html).
It handles announcing it and closing it on its own, so you only bring the
look.

Use it for messages that don't need an answer, like "Profile updated" or "Posted".
For a message the user has to answer, use an [Alert](/headless/alert)
instead.

```tsx
import { Toast, ToastArea } from "@wondesign/headless/Toast";
// or
import { Toast, ToastArea } from "@wondesign/ui/headless";
```

For ready-made styled toasts, use [`@wondesign/toast`](/components/toast),
which builds on `Toast`. Its `Toaster` lets you show one from anywhere with
an imperative API, `toast()`.

---

## Key Features

- ✅ **Accessible by Default**: Announced to screen readers without moving focus
- ✅ **Closes on Its Own**: Closes after a set time, or stays until it's closed
- ✅ **Waits for the User**: Pauses while hovered or focused
- ✅ **Many Toasts, One Area**: Show several toasts together in a single area
- ✅ **Controlled & Uncontrolled**: Let it manage the open state, or drive it yourself
- ✅ **Exit Animations**: A closed toast stays until its exit animation finishes
- ✅ **Composable**: Render your own elements with [`asChild`](/headless/as-child)

---

## Structure

For how to control, extend and style it, refer to the
[Usage tab](/headless/toast/usage). For what each prop does, refer to the
[API tab](/headless/toast/api).

- 🧩 **ToastArea**: the area every toast shows in, rendered once
- 🧩 **Toast**: one toast, with its own open state and timer
- 🧩 **ToastMessage**: the main line of the toast
- 🧩 **ToastDescription**: optional detail under the message
- 🧩 **ToastClose**: a button that closes the toast

```tsx
<ToastArea>
  <Toast isOpen={isSaved} onOpenChange={setSaved}>
    <ToastMessage>Saved</ToastMessage>
    <ToastDescription>Your changes are live.</ToastDescription>
    <ToastClose>Dismiss</ToastClose>
  </Toast>
</ToastArea>
```

`Toast` has no dot syntax, like `Toast.Message`. Import each part on its own.

## Known Issues

- 🐞 **Focus is lost when a toast closes**: If focus is inside a toast when it
  closes, by `ToastClose` or <Keyboard>Esc</Keyboard>, it **moves to the start
  of the page**, and the user loses their place.

---

## Watch Out

- ⚠️ **Keep everything else out of the area**: `ToastArea` is a live region,
  so **anything inside it is announced** to screen readers when it changes.
- ⚠️ **Rendering in place**: With `disablePortal`, the area stays inside its
  parent, so **an `overflow` or stacking context there can clip or cover the
  toasts**.

---

## Upcoming Features

- 🔜 **Shortcut to the Toasts**: Jump to the toasts with a keyboard shortcut, instead of tabbing to the end of the page
- 🔜 **Pause When the Page Is Hidden**: The timer pauses while the tab is in the background or the window loses focus, so toasts don't close unseen
- 🔜 **Swipe to Dismiss**: Close a toast by swiping it away on touch screens
