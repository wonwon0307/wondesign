# Usage

This page covers how to control, extend and style `Toast`. For what each prop
does, refer to the [API tab](/headless/toast/api).

---

## Setting Up the Area

`ToastArea` is required. Render it once, near the root of your app, and put
every toast inside it. **A `Toast` outside it throws an error.**

```tsx
function App() {
  return (
    <>
      <Header />
      <main>…</main>
      <ToastArea>
        <Toast>…</Toast>
        <Toast>…</Toast>
      </ToastArea>
    </>
  );
}
```

---

## Open State

`Toast` keeps its own state and starts closed. Pass `defaultOpen` to start it
open, or `isOpen` and `onOpenChange` to control it yourself. Both modes are
powered by [Disclosure](/interactions/disclosure/open-state/usage), so
they behave exactly as described there:

```tsx
// uncontrolled, starts closed
<Toast>…</Toast>;

// uncontrolled, starts open
<Toast defaultOpen>…</Toast>;

// controlled
const [open, setOpen] = useState(false);

<Toast isOpen={open} onOpenChange={setOpen}>
  …
</Toast>;
```

Use `defaultOpen` only for a toast you show once, like a welcome message.
`Toast` has no trigger, so **a toast that starts open can't be opened again
once it closes**. Control it if you need to show it more than once.

### Showing Toasts from Anywhere

Controlling the open state of every toast yourself gets repetitive.
[`@wondesign/toast`](/components/toast) works well for this: place its
`Toaster` once, then call its imperative API, `toast()`, from anywhere:

```tsx
import { toast } from "@wondesign/toast";

toast.success("Saved");
```

---

## Duration

The toast closes after 5 seconds by default. Pass `duration`, in
milliseconds, to change it, or `0` to keep it open until it's closed. A toast
that stays open needs a way to close it, like `ToastClose`:

```tsx
// closes after 10 seconds
<Toast duration={10000}>…</Toast>;

// stays open until closed
<Toast duration={0}>
  {/* … */}
  <ToastClose>Dismiss</ToastClose>
</Toast>;
```

---

## Running an Action

Pass `onClick` to `ToastClose` to run an action. It runs your `onClick`
first, then closes the toast, so you don't need to do it yourself. To skip
that in certain cases, call `event.preventDefault()`:

```tsx
const handleUndo = (event) => {
  if (!canUndo) {
    event.preventDefault(); // keeps the toast open
    return;
  }
  undo();
};

<Toast>
  <ToastMessage>File deleted</ToastMessage>
  <ToastClose onClick={handleUndo}>Undo</ToastClose>
</Toast>;
```

## Custom Parts

`useToast` gives any component inside `Toast` the open state, a way to close
it, and control over the timer. For example, a link that closes the toast
after going somewhere:

```tsx
import { useToast } from "@wondesign/headless/Toast";

function ViewLink() {
  const { dismissToast } = useToast();

  return (
    <a href="/files" onClick={dismissToast}>
      View
    </a>
  );
}
```

`resumeTimer` **doesn't check whether the toast is still hovered or
focused**, so calling it then can close the toast under the user.

## Your Own Elements

Every part takes `asChild`, which renders your own element or component
instead, like another heading level for the message:

```tsx
<ToastMessage asChild>
  <h4>Saved</h4>
</ToastMessage>
```

For how props and refs are merged, refer to
[AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/toast/api), so you can style
each state without extra props:

```css
.toast[data-paused] { … }
.close[data-disabled] { … }
```

### Exit Animations

Animate each toast with CSS, using its `data-state`. When it closes, it stays
on the page until its animations and transitions finish, including those
inside it:

```css
.toast[data-state="open"] {
  animation: slide-in 200ms;
}

.toast[data-state="closed"] {
  animation: slide-out 200ms;
}
```

While it's leaving, it can't be clicked or focused. **Animations that repeat
forever aren't waited for.**

### Showing the Time Left

A bar that shrinks over the `duration` can stop with the timer, using
`data-paused`. Stop it when the toast closes as well. Otherwise, a toast
closed early **stays until the bar runs out**, and one closed while paused
**never leaves**:

```css
.progress {
  animation: shrink 5000ms linear forwards; /* same as `duration` */
}

.toast[data-paused] .progress {
  animation-play-state: paused;
}

.toast[data-state="closed"] .progress {
  animation: none;
}
```
