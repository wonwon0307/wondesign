# Usage

This page covers how to control, extend and style `Modal`. For what each prop
does, refer to the [API tab](/headless/modal/api).

---

## Open State

`Modal` keeps its own state and starts closed. Pass `defaultOpen` to start it
open, or `isOpen` and `onOpenChange` to control it yourself. Both modes are
powered by [Disclosure](/interactions/disclosure/open-state/usage), so
they behave exactly as described there:

```tsx
// uncontrolled, starts closed
<Modal>…</Modal>;

// uncontrolled, starts open
<Modal defaultOpen>…</Modal>;

// controlled
const [open, setOpen] = useState(false);

<Modal isOpen={open} onOpenChange={setOpen}>
  …
</Modal>;
```

---

## Running an Action

Pass `onClick` to `Modal.Trigger` or `Modal.Close` to run an action. It runs
your `onClick` first, then opens or closes the modal, so you don't need to do
it yourself. To skip that in certain cases, call `event.preventDefault()`:

```tsx
const handleEditClick = (event) => {
  if (!isSignedIn) {
    event.preventDefault(); // keeps the modal closed
    redirectToSignIn();
  }
};

const handleSave = (event) => {
  if (!isValid) {
    event.preventDefault(); // keeps the modal open
    return;
  }
  saveProfile();
};

<Modal>
  <Modal.Trigger onClick={handleEditClick}>Edit profile</Modal.Trigger>
  <Modal.Content>
    {/* … */}
    <Modal.Close>Cancel</Modal.Close>
    <Modal.Close onClick={handleSave}>Save</Modal.Close>
  </Modal.Content>
</Modal>;
```

### Async Actions

The modal closes right after `onClick` runs. **It doesn't wait for a returned
promise**, so a failing action can't keep it open. To keep it open until an
action finishes, call `event.preventDefault()`, show the progress with
`isLoading`, and close the modal yourself with `closeModal` from
[`useModal`](#custom-parts):

```tsx
import { Modal, useModal } from "@wondesign/headless/Modal";

function SaveButtons() {
  const { closeModal } = useModal();
  const [isSaving, setSaving] = useState(false);

  const handleSave = async (event: React.MouseEvent) => {
    event.preventDefault(); // keeps the modal open
    setSaving(true);

    try {
      await saveProfile();
      closeModal();
    } finally {
      setSaving(false);
    }
  };

  return (
    <>
      <Modal.Close isDisabled={isSaving}>Cancel</Modal.Close>
      <Modal.Close isLoading={isSaving} onClick={handleSave}>
        Save
      </Modal.Close>
    </>
  );
}
```

While the action runs, a click outside and <Keyboard>Esc</Keyboard> **can
still close the modal**. To block them, control the modal and ignore closes in
`onOpenChange` until the action is done.

## Focus Management

By default, focus moves to the first focusable element inside the content when
the modal opens, and returns to `Modal.Trigger` when it closes. Pass
`initialFocusRef` to start somewhere else, and `returnFocusRef` to send it
somewhere else on close.

`initialFocusRef` must point inside the content. Outside it, **it's ignored
silently**, and focus moves to the first focusable element instead:

```tsx
const nameRef = useRef<HTMLInputElement>(null);
const settingsRef = useRef<HTMLButtonElement>(null);

<Modal initialFocusRef={nameRef} returnFocusRef={settingsRef}>
  <Modal.Trigger>Edit profile</Modal.Trigger>
  <Modal.Content>
    <Modal.Title>Profile</Modal.Title>
    <input ref={nameRef} aria-label="Name" />
    {/* … */}
  </Modal.Content>
</Modal>;
```

Moving focus in and back is handled by
[Auto Focus](/interactions/focus/auto-focus/usage), and keeping it inside by
[Focus Trap](/interactions/focus/focus-trap/usage), so both behave exactly as
described there.

## Adding a Backdrop

`Modal.Backdrop` renders a layer for you to style, like a dimmed overlay. It's
optional, and a click on it **closes the modal**, like any other click outside
the content. Portals are handled for you, so place it next to the content, or
wrap the content with it:

```tsx
// next to the content: one portal each
<Modal.Backdrop />
<Modal.Content>…</Modal.Content>

// wrapping the content: one portal for both
<Modal.Backdrop>
  <Modal.Content>…</Modal.Content>
</Modal.Backdrop>
```

The content isn't shown in the browser's top layer, so the `::backdrop`
pseudo-element doesn't apply. Use `Modal.Backdrop` instead.

## Custom Parts

`useModal` gives any component inside `Modal` the open state and ways to open
or close it. For example, a menu item that opens the modal:

```tsx
import { useModal } from "@wondesign/headless/Modal";

function EditMenuItem() {
  const { openModal } = useModal();

  return (
    <div role="menuitem" onClick={openModal}>
      Edit
    </div>
  );
}
```

## Your Own Elements

Every part except the provider and `Modal.Backdrop` takes `asChild`, which
renders your own element or component instead, like another heading level for
the title:

```tsx
<Modal.Title asChild>
  <h3>Edit profile</h3>
</Modal.Title>
```

For how props and refs are merged, refer to
[AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/modal/api), so you can style
each state without extra props:

```css
.trigger[data-state="open"] { … }
.backdrop[data-state="open"] { … }
.content[data-state="open"] { … }
.close[data-loading] { … }
```

### Exit Animations

Animate the content and backdrop with CSS, using their `data-state`. When the
modal closes, each one stays on the page until its own animations and
transitions finish:

```css
.backdrop[data-state="open"],
.content[data-state="open"] {
  animation: fade-in 200ms;
}

.backdrop[data-state="closed"],
.content[data-state="closed"] {
  animation: fade-out 200ms;
}
```

While they're leaving, they can't be clicked or focused, and screen readers
treat them as closed. The page behind doesn't wait: it's usable again as soon
as the modal closes. **Animations that repeat forever aren't waited for.**
