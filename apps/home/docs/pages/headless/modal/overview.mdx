# Modal

`Modal` shows content on top of the page until the user is done, following the
[WAI-ARIA Dialog (Modal) pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).
It handles the open state and focus, and blocks the page behind, so you only
bring the look.

Use it when the user has to finish a step before carrying on. For content that
belongs next to its trigger, use a [Popover](/headless/popover) instead. For
an urgent message that needs an answer, use an [Alert](/headless/alert)
instead.

```tsx
import { Modal } from "@wondesign/headless/Modal";
// or
import { Modal } from "@wondesign/ui/headless";
```

---

## Key Features

- ✅ **Accessible by Default**: Announced as a modal dialog, named by its title
- ✅ **Easy to Dismiss**: Closes with a close button, a click outside, or <Keyboard>Esc</Keyboard>
- ✅ **Focus Management**: Moves focus in, keeps it inside, and returns it on close
- ✅ **Blocks the Page Behind**: Nothing behind it can be focused or scrolled
- ✅ **Optional Backdrop**: Add a layer behind it, or leave it out
- ✅ **Controlled & Uncontrolled**: Let it manage the open state, or drive it yourself
- ✅ **Keep Content Mounted**: Hide closed content instead of removing it
- ✅ **Exit Animations**: Closed content stays until its exit animation finishes
- ✅ **Composable**: Render your own elements with [`asChild`](/headless/as-child)

## Structure

For how to control, extend and style it, refer to the
[Usage tab](/headless/modal/usage). For what each prop does, refer to the
[API tab](/headless/modal/api).

- 🧩 **Modal**: holds the open state, manages focus and blocks the page behind
- 🧩 **Modal.Trigger**: the button that opens the modal
- 🧩 **Modal.Backdrop**: an optional layer behind the modal
- 🧩 **Modal.Content**: the modal dialog itself
- 🧩 **Modal.Title**: the heading that names the modal
- 🧩 **Modal.Close**: a button that closes the modal

```tsx
// compound component, with its parts attached
<Modal>
  <Modal.Trigger>Edit profile</Modal.Trigger>
  <Modal.Backdrop />
  <Modal.Content>
    <Modal.Title>Edit profile</Modal.Title>
    {/* … */}
    <Modal.Close>Cancel</Modal.Close>
    <Modal.Close onClick={saveProfile}>Save</Modal.Close>
  </Modal.Content>
</Modal>;

// or, with named exports
<ModalProvider>
  <ModalTrigger>Edit profile</ModalTrigger>
  <ModalBackdrop />
  <ModalContent>
    <ModalTitle>Edit profile</ModalTitle>
    {/* … */}
    <ModalClose>Cancel</ModalClose>
    <ModalClose onClick={saveProfile}>Save</ModalClose>
  </ModalContent>
</ModalProvider>;
```

## Known Issues

- 🐞 **Nested overlays close the modal**: Clicking inside a popover, tooltip or
  other overlay opened from inside the modal counts as a click outside, and
  closes it.
- 🐞 **Content added in the background while the modal is open**: It can still
  be clicked and focused.
- 🐞 **The page shifts sideways**: Where scrollbars take up space, the page
  shifts by the scrollbar's width while the modal is open.

---

## Watch Out

- ⚠️ **Use named exports in Server Components**: The parts are client
  components, so a Server Component **can't reach `Modal.Trigger` through
  `Modal`**. Import `ModalTrigger` and the other parts on their own instead.
- ⚠️ **Reset the dialog's default styles**: The content renders a `<dialog>`,
  which browsers give a default margin, border, padding and background.
  Without resetting them, **the content lands in the wrong place** with no
  error. Set `margin: 0`, or use [Reset CSS](/styling/reset-css), which resets
  all of them.
- ⚠️ **Match the backdrop's and content's animations**: It's strongly
  recommended to give the backdrop and content exit animations of the same
  duration. Otherwise, `isPresent` and `status` from `useModal` can change
  while the backdrop is still on screen.
- ⚠️ **Closed content can stay visible**: With `keepMounted`, a `display`
  value in your styles overrides the `hidden` attribute, so **it stays
  visible** with no error. Set the `display` only while it's open, with
  `[data-state="open"]`.
- ⚠️ **Rendering in place**: With `disablePortal`, the backdrop and content
  stay inside their parents, so **an `overflow` or stacking context there can
  clip or cover them**.
