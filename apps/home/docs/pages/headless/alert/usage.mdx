# Usage

This page covers how to control, extend and style `Alert`. For what each prop
does, refer to the [API tab](/headless/alert/api).

To see real, styled examples of `Alert`, go to the
[Examples tab](/components/alert/examples) of `@wondesign/alert`.

---

## Open State

`Alert` keeps its own state and starts closed. Pass `defaultOpen` to start it
open, or `isOpen` and `onOpenChange` to control it yourself. Both modes are
powered by [Disclosure](/interactions/disclosure/open-state/usage), so
they behave exactly as described there:

```tsx
// uncontrolled, starts closed
<Alert>…</Alert>;

// uncontrolled, starts open
<Alert defaultOpen>…</Alert>;

// controlled
const [open, setOpen] = useState(false);

<Alert isOpen={open} onOpenChange={setOpen}>
  …
</Alert>;
```

### Showing Alerts from Anywhere

Controlling the open state of every alert yourself gets repetitive.
[`@wondesign/alert`](/components/alert) works well for this: place its
`Alerter` once, then call `showAlert` or `showConfirm` from anywhere, and await
the answer:

```tsx
import { showConfirm } from "@wondesign/alert";

const confirmed = await showConfirm(
  "Log out?",
  "You'll need to sign in again.",
);
```

## Running an Action

Pass `onClick` to `Alert.Trigger` or `Alert.Close` to run an action. It runs
your `onClick` first, then opens or closes the alert, so you don't need to do
it yourself. To skip that in certain cases, call `event.preventDefault()`:

```tsx
const handleDeleteClick = (event) => {
  if (selectedFiles.length === 0) {
    event.preventDefault(); // keeps the alert closed
    showToast("Select a file first");
  }
};

<Alert>
  <Alert.Trigger onClick={handleDeleteClick}>Delete</Alert.Trigger>
  <Alert.Content>
    {/* … */}
    <Alert.Close>Cancel</Alert.Close>
    <Alert.Close onClick={deleteFiles}>Delete</Alert.Close>
  </Alert.Content>
</Alert>;
```

### Async Actions

The alert closes right after `onClick` runs. **It doesn't wait for a returned
promise**, so a failing action can't keep it open. To keep it open until an
action finishes, call `event.preventDefault()`, show the progress with
`isLoading`, and close the alert yourself with `closeAlert` from
[`useAlert`](#custom-parts):

```tsx
import { Alert, useAlert } from "@wondesign/headless/Alert";

function DeleteButtons() {
  const { closeAlert } = useAlert();
  const [isDeleting, setDeleting] = useState(false);

  const handleDelete = async (event: React.MouseEvent) => {
    event.preventDefault(); // keeps the alert open
    setDeleting(true);

    try {
      await deleteFile();
      closeAlert();
    } finally {
      setDeleting(false);
    }
  };

  return (
    <>
      <Alert.Close isDisabled={isDeleting}>Cancel</Alert.Close>
      <Alert.Close isLoading={isDeleting} onClick={handleDelete}>
        Delete
      </Alert.Close>
    </>
  );
}
```

While the action runs, <Keyboard>Esc</Keyboard> **can still close the alert**.
To block it, control the alert and ignore closes in `onOpenChange` until the
action is done.

## Focus Management

By default, focus moves to the first focusable element inside the content when
the alert opens, usually the first close button, and returns to
`Alert.Trigger` when it closes. Pass `initialFocusRef` to start somewhere
else, and `returnFocusRef` to send it somewhere else on close.

`initialFocusRef` must point inside the content. Outside it, **it's ignored
silently**, and focus moves to the first focusable element instead:

```tsx
const cancelRef = useRef<HTMLButtonElement>(null);
const settingsRef = useRef<HTMLButtonElement>(null);

<Alert initialFocusRef={cancelRef} returnFocusRef={settingsRef}>
  <Alert.Trigger>Delete account</Alert.Trigger>
  <Alert.Content>
    {/* … */}
    <Alert.Close ref={cancelRef}>Cancel</Alert.Close>
    <Alert.Close onClick={deleteAccount}>Delete</Alert.Close>
  </Alert.Content>
</Alert>;
```

Moving focus in and back is handled by
[Auto Focus](/interactions/focus/auto-focus/usage), and keeping it inside by
[Focus Trap](/interactions/focus/focus-trap/usage), so both behave exactly as
described there.

## Adding a Backdrop

`Alert.Backdrop` renders a layer for you to style, like a dimmed overlay. It's
optional, and it **doesn't close the alert when clicked**. Portals are handled
for you, so place it next to the content, or wrap the content with it:

```tsx
// next to the content: one portal each
<Alert.Backdrop />
<Alert.Content>…</Alert.Content>

// wrapping the content: one portal for both
<Alert.Backdrop>
  <Alert.Content>…</Alert.Content>
</Alert.Backdrop>
```

## Custom Parts

`useAlert` gives any component inside `Alert` the open state and ways to open
or close it. For example, a menu item that opens the alert:

```tsx
import { useAlert } from "@wondesign/headless/Alert";

function DeleteMenuItem() {
  const { showAlert } = useAlert();

  return (
    <div role="menuitem" onClick={showAlert}>
      Delete
    </div>
  );
}
```

## Your Own Elements

Every part except the provider and `Alert.Backdrop` takes `asChild`, which
renders your own element or component instead, like another heading level for
the title:

```tsx
<Alert.Title asChild>
  <h3>Delete this file?</h3>
</Alert.Title>
```

For how props and refs are merged, refer to
[AsChild](/headless/as-child/usage).

## Styling

Style each part with `className` and `style`, like any other element. Their
states show up as [data attributes](/headless/alert/api), so you can style
each state without extra props:

```css
.content[data-state="open"] { … }
.close[data-disabled] { … }
```

### Exit Animations

Animate the content and backdrop with CSS, using their `data-state`. When the
alert closes, each one stays on the page until its own animations and
transitions finish:

```css
.backdrop[data-state="open"],
.content[data-state="open"] {
  animation: fade-in 200ms;
}

.backdrop[data-state="closed"],
.content[data-state="closed"] {
  animation: fade-out 200ms;
}
```

While they're leaving, they can't be clicked or focused, and screen readers
treat them as closed. The page behind doesn't wait: it's usable again as soon
as the alert closes. **Animations that repeat forever aren't waited for.**
