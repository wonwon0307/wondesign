# Alert

`Alert` interrupts the user with an urgent message and waits for a response,
following the
[WAI-ARIA Alert Dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/),
not the WAI-ARIA Alert pattern despite its name. It handles the open state and
focus, and blocks the page behind, so you only bring the look.

Use it when the user has to answer before they carry on. For messages that
don't need an answer, use a [Toast](/headless/toast) instead. For content
that isn't urgent, use a [Modal](/headless/modal) instead.

```tsx
import { Alert } from "@wondesign/headless/Alert";
// or
import { Alert } from "@wondesign/ui/headless";
```

For ready-made styled alerts, use [`@wondesign/alert`](/components/alert),
which builds on `Alert`. Its `Alerter` lets you open one from anywhere with
`showAlert` or `showConfirm`.

---

## Key Features

- ✅ **Accessible by Default**: Announced as an alert dialog, with its title and message
- ✅ **Focus Management**: Moves focus in, keeps it inside, and returns it on close
- ✅ **Blocks the Page Behind**: Nothing behind it can be clicked, focused or scrolled
- ✅ **Optional Backdrop**: Add a layer behind it, or leave it out
- ✅ **Controlled & Uncontrolled**: Let it manage the open state, or drive it yourself
- ✅ **Keep Content Mounted**: Hide closed content instead of removing it
- ✅ **Exit Animations**: Closed content stays until its exit animation finishes
- ✅ **Composable**: Render your own elements with [`asChild`](/headless/as-child)

---

## Structure

For how to control, extend and style it, refer to the
[Usage tab](/headless/alert/usage). For what each prop does, refer to the
[API tab](/headless/alert/api).

- 🧩 **Alert**: holds the open state, manages focus and blocks the page behind
- 🧩 **Alert.Trigger**: the button that opens the alert
- 🧩 **Alert.Backdrop**: an optional layer behind the alert
- 🧩 **Alert.Content**: the alert dialog itself
- 🧩 **Alert.Title**: the heading that names the alert
- 🧩 **Alert.Message**: the text that describes the alert
- 🧩 **Alert.Close**: a button that closes the alert

```tsx
// compound component, with its parts attached
<Alert>
  <Alert.Trigger>Log out</Alert.Trigger>
  <Alert.Backdrop />
  <Alert.Content>
    <Alert.Title>Log out?</Alert.Title>
    <Alert.Message>You'll need to sign in again.</Alert.Message>
    <Alert.Close>Cancel</Alert.Close>
    <Alert.Close onClick={logOut}>Log out</Alert.Close>
  </Alert.Content>
</Alert>;

// or, with named exports
<AlertProvider>
  <AlertTrigger>Log out</AlertTrigger>
  <AlertBackdrop />
  <AlertContent>
    <AlertTitle>Log out?</AlertTitle>
    <AlertMessage>You'll need to sign in again.</AlertMessage>
    <AlertClose>Cancel</AlertClose>
    <AlertClose onClick={logOut}>Log out</AlertClose>
  </AlertContent>
</AlertProvider>;
```

## Known Issues

- 🐞 **Content added in the background while the alert is open**: It can
  still be clicked and focused.
- 🐞 **The page shifts sideways**: Where scrollbars take up space, the page
  shifts by the scrollbar's width while the alert is open.

---

## Watch Out

- ⚠️ **Use named exports in Server Components**: The parts are client
  components, so a Server Component **can't reach `Alert.Trigger` through
  `Alert`**. Import `AlertTrigger` and the other parts on their own instead.
- ⚠️ **Match the backdrop's and content's animations**: It's strongly
  recommended to give the backdrop and content exit animations of the same
  duration. Otherwise, `isPresent` and `status` from `useAlert` can change
  while the backdrop is still on screen.
- ⚠️ **Closed content can stay visible**: With `keepMounted`, a `display`
  value in your styles overrides the `hidden` attribute, so **it stays
  visible** with no error. Set the `display` only while it's open, with
  `[data-state="open"]`.
- ⚠️ **Rendering in place**: With `disablePortal`, the backdrop and content
  stay inside their parents, so **an `overflow` or stacking context there can
  clip or cover them**.
