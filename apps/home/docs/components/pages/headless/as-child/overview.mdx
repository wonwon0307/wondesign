# AsChild

Every headless component renders a default element, like a `<button>` or a
`<nav>`. With `asChild`, you swap it for your own element and keep all of the
component's behaviour.

```tsx
import Link from "next/link";
import { Button } from "@wondesign/headless/Button";

<Button asChild>
  <Link href="/pricing">See pricing</Link>
</Button>;
```

See [Usage](/components/headless/as-child/usage) for the two ways to use it,
what your child needs, and where to put your props.

---

## Key Features

- ✅ **Keep the Behaviour**: Your element gets the component's ARIA attributes, state and handlers
- ✅ **Bring Any Element**: Native elements, router links, or your own components
- ✅ **Nothing Gets Lost**: Classes, styles, event handlers and refs from both sides are combined

---

## How It Works

When the component and your element both set the same prop:

- 🔗 **`className`**: both are kept
- 🔗 **`style`**: both are merged, and yours wins on conflicts
- 🔗 **`ref`**: both are attached
- 🔗 **Event handlers**: both run — yours first, then the component's
- 🔗 **Anything else**: the component's wins, if it sets one

```tsx
<Tooltip.Trigger
  asChild
  className="trigger"
  style={{ color: "gray", padding: 4 }}
  onClick={trackTrigger}
>
  <button
    ref={ref}
    type="submit"
    className="icon-button"
    style={{ color: "blue" }}
    onClick={trackButton}
  >
    Help
  </button>
</Tooltip.Trigger>

// className → "trigger icon-button"
// style     → { color: "blue", padding: 4 }
// ref       → the trigger's own, and `ref`
// onClick   → trackButton, then trackTrigger
// type      → "button", the trigger's own, so "submit" is ignored
```

---

## Watch Out

- ⚠️ **One element only**: The child must be a single element. Text or several
  children **render nothing**, with a warning in development.

  ```tsx
  // ✅ good
  <Button asChild>
    <a href="/pricing">See pricing</a>
  </Button>

  // ❌ bad - two children, so nothing renders
  <Button asChild>
    <Icon />
    <span>See pricing</span>
  </Button>
  ```

  The single element can be your own component too. See
  [Custom Components](/components/headless/as-child/usage#custom-components)
  for what it needs.

- ⚠️ **Handlers on the child aren't blocked**: When a component blocks
  interactions, like a disabled [Button](/components/headless/button/overview#known-issues),
  it only blocks the handlers passed to it. Handlers written on the child still
  run. Pass them to the component instead, as described in
  [Notes](/components/headless/as-child/usage#notes).

## Supported Components

- 🔘 **[Button](/components/headless/button)**
- 🧩 **[Alert](/components/headless/alert)**: `Alert.Trigger`, `Alert.Content`,
  `Alert.Title`, `Alert.Message`, `Alert.Close`
- 🧩 **[Collapsible](/components/headless/collapsible)**: `Collapsible.Toggle`,
  `Collapsible.Content`
- 🧩 **[Popover](/components/headless/popover)**: `Popover.Trigger`,
  `Popover.Content`, `Popover.Title`, `Popover.Close`
- 🧩 **[Tabs](/components/headless/tabs)**: `Tabs.List`, `Tabs.Tab`, `Tabs.Panel`
- 🧩 **[Toast](/components/headless/toast)**: `ToastArea`, `Toast`,
  `ToastMessage`, `ToastDescription`, `ToastClose`
- 🧩 **[Tooltip](/components/headless/tooltip)**: `Tooltip.Trigger`,
  `Tooltip.Content`

`Anchor`, and every component built on it, take an `as` prop instead, for rendering a router
link. See the [Anchor](/components/headless/anchor/usage#router-links) document for details.
