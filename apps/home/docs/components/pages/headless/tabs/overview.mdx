# Tabs

`Tabs` shows one panel at a time, chosen from a list of tabs, following the
[WAI-ARIA Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). It
handles selection, keyboard navigation and the wiring between each tab and its
panel, so you only bring the look.

Use it to split related content into views the user switches between on the
same page, like the sections of a settings page, or a product's description,
specs and reviews. For tabs that navigate between pages, like a row of links
styled as tabs, **use [Navbar](/components/navbar) instead**.

---

## Key Features

- ✅ **Accessible by Default**: Each tab is linked to its panel for assistive technology
- ✅ **Keyboard Navigation**: Move between tabs with the arrow keys, <Keyboard>Home</Keyboard> and <Keyboard>End</Keyboard>, then <Keyboard>Tab</Keyboard> into the panel
- ✅ **Controlled & Uncontrolled**: Let it manage the selected tab, or drive it yourself
- ✅ **Horizontal & Vertical**: Arrow keys follow the direction of the list
- ✅ **Disabled Tabs**: Turn off a single tab, or all of them
- ✅ **Keep Panels Mounted**: Hide inactive panels instead of removing them
- ✅ **Composable**: Render your own elements with [`asChild`](/components/headless/as-child)

## Structure

For what you can configure, refer to the
[Usage tab](/components/headless/tabs/usage). For every prop, refer to the
[API tab](/components/headless/tabs/api).

- 🧩 **Tabs**: coordinates every part. It holds the selected tab, links each
  tab to its panel, and shares settings like `isDisabled`. **Renders no element
  of its own.**
- 🧩 **Tabs.List**: the container that groups the tabs.
- 🧩 **Tabs.Tab**: a button that selects its panel.
- 🧩 **Tabs.Panel**: the content shown for its tab.

```tsx
<Tabs defaultTab="account">
  <Tabs.List aria-label="Settings">
    <Tabs.Tab tabName="account">Account</Tabs.Tab>
    <Tabs.Tab tabName="billing">Billing</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel tabName="account">…</Tabs.Panel>
  <Tabs.Panel tabName="billing">…</Tabs.Panel>
</Tabs>;

// or, with named exports
<TabsProvider defaultTab="account">
  <TabsList aria-label="Settings">
    <Tab tabName="account">Account</Tab>
    <Tab tabName="billing">Billing</Tab>
  </TabsList>
  <TabPanel tabName="account">…</TabPanel>
  <TabPanel tabName="billing">…</TabPanel>
</TabsProvider>;
```

## How It Works

A set of tabs has to work like a single control from the keyboard, and tell
the user which tab is selected and which panel belongs to it. `Tabs` builds
this in, following the
[WAI-ARIA Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/): it
decides how focus moves between the tabs, how a tab is selected, and what
screen readers announce. You don't need to wire up any of it.

### Keyboard

The tab list is **a single <Keyboard>Tab</Keyboard> stop**:

<Keyboard>Tab</Keyboard> lands on the selected tab, and the next
<Keyboard>Tab</Keyboard> moves into its panel. Inside the list,
<Keyboard>←</Keyboard> and <Keyboard>→</Keyboard> move between the tabs, or
<Keyboard>↑</Keyboard> and <Keyboard>↓</Keyboard> in a vertical list, and
<Keyboard>Home</Keyboard> and <Keyboard>End</Keyboard> jump to the first and
last one.

A click, <Keyboard>Enter</Keyboard> or <Keyboard>Space</Keyboard> selects the
focused tab. Moving between the tabs is handled by
[Arrow Navigation](/foundations/focus/arrow-navigation).

### Screen Readers

The list is announced as a set of tabs, with its label. Each tab is announced
as selected or not, and points screen readers to its panel. Each panel is
labelled by its tab.
