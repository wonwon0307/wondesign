# Usage

This page covers what you can configure on `Alert`. For every prop, refer to
the [API tab](/components/headless/alert/api).

---

## Running an Action

Every close button closes the alert, **including the one that confirms**. Run
the action itself in `onClick`. You don't need to close the alert yourself:
`Alert.Close` does it after `onClick`.

```tsx
<Alert.Close>Cancel</Alert.Close>
<Alert.Close onClick={logOut}>Log out</Alert.Close>
```

Both are `Alert.Close`, so nothing tells them apart but your styles.
Make the one that runs an action look different from the ones that
only close, so the user can tell which one acts.

### Async Actions

The alert closes right after `onClick` runs. **It doesn't wait for a returned
promise**, so a failing action can't keep it open. To keep the alert open
until an action finishes, call `event.preventDefault()` in `onClick`, and
close the alert yourself once the action is done, by controlling it or with
`closeAlert` from [`useAlert`](#building-your-own-parts).

The alert doesn't know about your action, so while it runs, **the close
buttons stay enabled, and <Keyboard>Esc</Keyboard> still closes the alert**.
Disable your buttons, and ignore closes in `onOpenChange` until the action is
done:

```tsx
const [open, setOpen] = useState(false);
const [isDeleting, setDeleting] = useState(false);

const handleDelete = async (event: React.MouseEvent) => {
  event.preventDefault(); // keeps the alert open
  setDeleting(true);

  try {
    await deleteFile();
    setOpen(false); // or `closeAlert()`, inside a component of your own
  } catch {
    showError("Couldn't delete the file"); // keeps the alert open
  } finally {
    setDeleting(false);
  }
};

<Alert isOpen={open} onOpenChange={(next) => !isDeleting && setOpen(next)}>
  {/*...*/}
  <Alert.Close isDisabled={isDeleting}>Cancel</Alert.Close>
  <Alert.Close isLoading={isDeleting} onClick={handleDelete}>
    Delete
  </Alert.Close>
</Alert>;
```

## Initial Focus

When the alert opens, focus moves to the first focusable element inside the
content. **Start on the least destructive response**: put "Cancel" before
"Delete" in the markup, and change the visual order with CSS if you need to:

```tsx
<Alert.Content>
  {/* focused when the alert opens */}
  <Alert.Close>Cancel</Alert.Close>
  <Alert.Close onClick={deleteFile}>Delete</Alert.Close>
</Alert.Content>
```

You can't choose another element to start on yet, like the title of a long
message so it's read from the top. For now, the order in the markup decides
where focus starts.

---

## Heading Level

`Alert.Title` renders an `<h2>`. Use `asChild` to render another heading
level:

```tsx
<Alert.Title asChild>
  <h3>Delete this file?</h3>
</Alert.Title>
```

## Open State

`Alert` keeps its own state and starts closed. Pass `defaultOpen` to start it
open, or `isOpen` and `onOpenChange` to control it yourself. Both modes are
powered by [Disclosure](/foundations/disclosure/open-state#how-it-works), so
they behave exactly as described there:

```tsx
// uncontrolled, starts closed
<Alert>…</Alert>;

// uncontrolled, starts open
<Alert defaultOpen>…</Alert>;

// controlled
const [open, setOpen] = useState(false);

<Alert isOpen={open} onOpenChange={setOpen}>
  …
</Alert>;
```

## Adding a Backdrop

`Alert.Backdrop` renders an empty layer for you to style, like a dimmed
overlay. It's optional, and it **doesn't close the alert when clicked**: like
the rest of the page, it can't be clicked at all while the alert is open.

The backdrop **doesn't accept children**, so it shouldn't be used to position
the content. Position the content yourself, and make sure it stays on top of
the backdrop, by its order in the document or with `z-index`:

```tsx
<Alert.Backdrop className="backdrop" />
<Alert.Content className="content">…</Alert.Content>
```

```css
.backdrop {
  position: fixed;
  inset: 0;
  z-index: 100;
  background: rgb(0 0 0 / 50%);
}

.content {
  position: fixed;
  top: 50%;
  left: 50%;
  z-index: 101;
  transform: translate(-50%, -50%);
}
```

## Rendering in Place

The backdrop and content render at the end of `<body>`, so they aren't
clipped by their parents. Pass `disablePortal` to `Alert` to render both where
they are in the document instead:

```tsx
<Alert disablePortal>…</Alert>
```

**Make sure you know what you're doing**: rendered in place, they can be clipped
by their parents or covered by other elements, and handling that is up to you.

---

## Keeping Content Mounted

Closed content is **removed from the page** by default. Pass `keepMounted` to
keep it in the page, hidden with the `hidden` attribute, so what's inside
keeps its state, like text typed into a field:

```tsx
<Alert keepMounted>…</Alert>
```

<Callout variant="warning" title="Closed content can stay visible">
  A `display` value in your styles overrides the `hidden` attribute, so **it
  stays visible** with no error. Set the `display` only while it's open, with
  `[data-state="open"]`.
</Callout>

## Building Your Own Parts

`useAlert` gives any component inside `Alert` the open state and ways to open
or close it. For example, a menu item that opens the alert:

```tsx
import { useAlert } from "@wondesign/headless/Alert";

function DeleteMenuItem() {
  const { showAlert } = useAlert();

  return (
    <div role="menuitem" onClick={showAlert}>
      Delete
    </div>
  );
}
```

For everything the hook returns, refer to the
[API tab](/components/headless/alert/api#usealert).

---

## Styling with Data Attributes

The parts expose their state as
[data attributes](/components/headless/alert/api), so you can style each state
with plain CSS:

```css
.content[data-state="open"] { … }
.close[data-disabled] { … }
```
