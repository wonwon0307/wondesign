# Collapsible

`Collapsible` pairs a toggle with a section of content it shows and hides. It
wires the two together for assistive technology, so you only bring the look.

---

## Key Features

- ✅ **Accessible by Default**: The toggle and content are linked for assistive technology
- ✅ **Controlled & Uncontrolled**: Let it manage its own state, or drive it yourself
- ✅ **Keep Content Mounted**: Hide closed content instead of removing it
- ✅ **Composable**: Render your own elements with `asChild`
- ✅ **Ref Forwarding**: Your `ref` reaches the toggle and content elements

---

## Structure

- 🧩 **Collapsible**: holds the open state. **Renders no element of its own.**
- 🧩 **Collapsible.Toggle**: the button that opens and closes the content.
- 🧩 **Collapsible.Content**: the section that's shown and hidden.

```tsx
<Collapsible>
  <Collapsible.Toggle>Show details</Collapsible.Toggle>
  <Collapsible.Content>…</Collapsible.Content>
</Collapsible>;

// or, with named exports
<CollapsibleProvider>
  <CollapsibleToggle>Show details</CollapsibleToggle>
  <CollapsibleContent>…</CollapsibleContent>
</CollapsibleProvider>;
```

## Usage

### Open State

`Collapsible` keeps its own state and starts closed. Pass `defaultOpen` to
start it open, or `isOpen` and `onOpenChange` to control it yourself. Both
modes are powered by [Disclosure](/foundations/disclosure#usage), so they
behave exactly as described there.

```tsx
// uncontrolled, starts open
<Collapsible defaultOpen>…</Collapsible>

// controlled
const [open, setOpen] = useState(false);

<Collapsible isOpen={open} onOpenChange={setOpen}>…</Collapsible>;
```

### Keeping Content Mounted

Closed content is **removed from the page** by default. Pass `keepMounted` to
hide it instead, so anything inside, like form inputs, keeps its state:

```tsx
<Collapsible keepMounted>
  <Collapsible.Toggle>Advanced options</Collapsible.Toggle>
  <Collapsible.Content>
    <input name="timeout" />
  </Collapsible.Content>
</Collapsible>
```

### Building Your Own Parts

`useCollapsible` gives any component inside a `Collapsible` its open state and
a `toggle` function. It throws an error when used outside a `Collapsible`:

```tsx
import { useCollapsible } from "@wondesign/headless/Collapsible";

function Chevron() {
  const { isOpen } = useCollapsible();

  return <ChevronIcon className={isOpen ? "rotated" : undefined} />;
}
```

### Styling with Data Attributes

The toggle and content expose their state as
[data attributes](/components/headless/collapsible/api), so you can style each
state with plain CSS:

```css
.toggle[data-state="open"] { … }
.content[data-state="open"] { … }
```

## Accessibility

Follows the
[WAI-ARIA Disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/).

- ⌨️ **Enter** or **Space** on the toggle opens and closes the content.
- ⌨️ **Tab** moves to the toggle, even while it's disabled.

The toggle tells assistive technology whether the content is open, and which
content it controls. When the content is a major section of the page, pass
`role="region"` to it, and it's labelled by its toggle.
