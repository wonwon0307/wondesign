# Usage

This page covers what you can configure on `Tooltip`. For every prop, refer to
the [API tab](/components/headless/tooltip/api).

---

## Positioning the Content

`useTooltip` gives you the position of the content and the arrow. **Apply them
yourself**, usually in a small wrapper of your own:

```tsx
import { Tooltip, useTooltip } from "@wondesign/headless/Tooltip";

function MyTooltipContent({ children }: { children: React.ReactNode }) {
  const { content } = useTooltip();

  return (
    <Tooltip.Content
      style={{
        position: "fixed",
        top: 0,
        left: 0,
        transform: `translate3d(${content.x}px, ${content.y}px, 0)`,
      }}
    >
      {children}
    </Tooltip.Content>
  );
}
```

The content's position is measured from the top left of the viewport. The
arrow's position is measured from the top left of the content, so position the
arrow `absolute` inside it the same way.

---

## Placement and Alignment

The default placement is `"bottom"`; pass `placement` to prefer another side.
The default alignment is `"center"`; pass `align` to line it up with the start
or end of the trigger instead:

```tsx
<Tooltip placement="right" align="start">
  …
</Tooltip>
```

Pass `forcePlacement` to **keep it on the side you chose**, even without room.
`offset` sets the gap from the trigger, and `padding` the space it keeps from
the edges of the viewport.

---

## Delays

On hover, the tooltip waits `showDelay` before showing, and `hideDelay` before
hiding. Focus and long press **ignore the delays**:

```tsx
<Tooltip showDelay={500} hideDelay={100}>
  …
</Tooltip>
```

---

## Open State

`Tooltip` keeps its own state and starts closed. Pass `isOpen` and
`onOpenChange` to control it yourself. Both modes are powered by
[Disclosure](/foundations/disclosure/open-state#how-it-works), so they behave
exactly as described there:

```tsx
// uncontrolled, starts closed
<Tooltip>…</Tooltip>;

// controlled
const [open, setOpen] = useState(false);

<Tooltip isOpen={open} onOpenChange={setOpen}>
  …
</Tooltip>;
```

---

## Disabling the Trigger

A trigger with `isDisabled` can't be pressed, but it **still shows its
tooltip** on hover, focus or long press. Use this to explain why it's
disabled:

```tsx
<Tooltip>
  <Tooltip.Trigger isDisabled>Save</Tooltip.Trigger>
  <Tooltip.Content>You have no changes to save</Tooltip.Content>
</Tooltip>
```

To show no tooltip at all, render a plain
[Headless Button](/components/headless/button) instead of the `Tooltip`.

---

## Rendering in Place

The content renders in a [Portal](/components/headless/portal) at the end of
`<body>`, so it isn't clipped by its parents. Pass `disablePortal` to render it
where it is in the document instead:

```tsx
<Tooltip.Content disablePortal>…</Tooltip.Content>
```

<Callout variant="warning" title="Compute the position yourself">
  The position from `useTooltip` is measured from the viewport, which suits
  content rendered in the Portal. When you render the content in place, work out
  its position yourself, relative to the element it ends up in.
</Callout>

---

## Keeping Content Mounted

Closed content is **removed from the page** by default. Pass `keepMounted` to
keep it in the page instead:

```tsx
<Tooltip keepMounted>…</Tooltip>
```

<Callout variant="warning" title="Closed content can stay visible">
  Closed content is only hidden from screen readers, so **it stays visible**
  with no error. Hide it in your styles, with `[data-state="closed"]`.
</Callout>

---

## Building Your Own Parts

`useTooltip` gives any component inside `Tooltip` the open state, the
position, and ways to show or hide it, with or without the delays. For example,
a help icon next to the trigger that opens the same tooltip on hover:

```tsx
import { useTooltip } from "@wondesign/headless/Tooltip";

function HelpIcon() {
  const { showWithDelay, hideWithDelay } = useTooltip();

  return (
    <span aria-hidden onMouseEnter={showWithDelay} onMouseLeave={hideWithDelay}>
      ?
    </span>
  );
}
```

The content is **still positioned against `Tooltip.Trigger`**, wherever it's
opened from.

For everything the hook returns, refer to the
[API tab](/components/headless/tooltip/api#usetooltip).

---

## Styling with Data Attributes

The content exposes its state as
[data attributes](/components/headless/tooltip/api), so you can style each
state with plain CSS:

```css
.content[data-state="open"] { … }
```
