# Using WonDesign's Semantic Colors

Getting colors into your app takes up to four steps — two of them optional,
depending on your setup.

---

## Steps

### 1. Choose a Palette

Pick the palette your app will use. See
[Palette](/foundations/colors/palette) for more details.

```ts
import { wondesignLight, wondesignDark } from "@wondesign/colors";
```

### 2. Merge light-dark() (optional)

If your app only ever uses one scheme, skip this step.

If you're looking to support both color schemes, merge your light and dark
palettes into one, and set up CSS so it switches correctly.

[`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark)
is a modern CSS API for defining a color for both color schemes at once. It
takes two colors — one for light mode, one for dark mode — and the browser
uses whichever matches the element's `color-scheme`. Since the browser makes
the choice, a single value covers both schemes, and switching between them
needs no media queries, extra classes, or JavaScript.

#### Compatibility

<Callout title="Modern browsers only" variant="warning">
  This package outputs CSS `light-dark()` (Baseline 2024) and `color-mix()`
  (Baseline 2023), which need Chrome / Edge 123+, Firefox 120+, or Safari 17.5+.
  Older browsers will ignore these values, so colors may not apply at all.
</Callout>

#### Setup

Refer to [`@wondesign/theme`'s documentation](/foundations/theme) to set up
your app to use `light-dark()`.

If you don't want to use `@wondesign/theme`, make sure to set
`color-scheme: light dark;` in the root CSS file:

```css
:root {
  color-scheme: light dark; /* follow the user's system setting */
}
```

#### mergeLightDark

`mergeLightDark()` merges your light and dark palettes into one. Every value
becomes a CSS `light-dark()` pair, so you can use the returned values across
your app, regardless of the current scheme.

```ts
import {
  mergeLightDark,
  wondesignLight,
  wondesignDark,
} from "@wondesign/colors";

const colors = mergeLightDark(wondesignLight, wondesignDark);
colors.primary; // "light-dark(#1647E8, #3B82F6)"
```

### 3. Set CSS variables (optional)

To reference your colors as CSS variables, you need to set these variables at
the root of the CSS tree. If you're using
[`@wondesign/tokens`](/foundations/tokens), `buildCssVariables` handles this
in a single call — pass your palette as `colors`, and include the resulting
CSS in your app:

```ts
import { buildCssVariables } from "@wondesign/tokens";

const css = buildCssVariables({ colors });
```

### 4. Use in styles

If you're using `@wondesign/tokens`, apply the colors through `tokens.colors`.
Refer to [the tokens documentation](/foundations/tokens) for more details.

```ts
import { tokens } from "@wondesign/tokens";

const button = {
  backgroundColor: tokens.colors.primary,
  color: tokens.colors.onPrimary,
};
```

Otherwise, apply the colors to your styles straight from your palette:

```ts
// `colors` from step 2, or a single palette such as `wondesignLight`
const button = {
  backgroundColor: colors.primary,
  color: colors.onPrimary,
};
```

## Advanced

### Extend SemanticColors

Declare a new interface that extends `SemanticColors` and add your roles:

```ts
import type { SemanticColors } from "@wondesign/colors";

export interface BrandColors extends SemanticColors {
  secondary: string;
  onSecondary: string;
  info: string;
}
```

`BrandColors` keeps all 18 built-in roles and adds three of its own. Because
it still satisfies `SemanticColors`, it can be used anywhere the package
expects one — and `mergeLightDark` keeps your extra roles in its return type:

```ts
const colors = mergeLightDark(brandLight, brandDark);
colors.secondary; // "light-dark(…, …)"
```

#### Things to Keep in Mind

- **Extend, don't remove.** You can add roles, but you can't leave built-in
  ones out — a palette without them no longer satisfies `SemanticColors`. If
  there's a role you don't need, simply don't use it.
- **Pair your foreground colors.** If you add a role that other content sits
  on, like `secondary`, consider adding its `on*` counterpart too, so text on
  it stays readable in both schemes.
- **Keep light and dark in sync.** Both palettes should define the same roles.
  Typing them with the same interface, as above, takes care of this for you.
