# Learn the WonDesign Semantic Colors

Every WonDesign palette implements the same `SemanticColors` interface — 18
keys, grouped by the role they play in the UI rather than by hue. Components
ask for "the muted text color" or "the surface color", never for "gray 500",
so a whole palette can be swapped without touching a single component.

```ts
import type { SemanticColors } from "@wondesign/colors";
```

---

## Color Roles

This section walks through the 18 semantic colors, grouped by role, with
suggestions on what each one is meant for and where it typically fits in a UI.
Treat them as a starting point rather than strict rules — every product is
different, so adapt them to whatever works best for yours.

### Primary

Your brand color, and the color of whatever sits on top of it.

- `primary` — The brand accent. Primary actions, links, selected and active states.
- `onPrimary` — Content placed on top of `primary`, e.g. a primary button's label and icon.

### Alerts

Status colors for feedback. They work best as text and icon colors — for
backgrounds, pair them with `colorWithFade` or `colorWithOpacity` for a softer tint.
See [the utilities page](/foundations/colors/utilities) for reference.

- `error` — Errors, destructive actions, invalid form fields.
- `warning` — Cautions and states that need attention but aren't failures.
- `success` — Confirmations and completed or valid states.

### Background

Used for `backgroundColor` — from the page itself to the layers stacked on top of it.

- `background` — The default background of the page itself; the base layer everything else sits on.
- `backgroundHighlight` — A translucent tint for hover states, and for any element you want to emphasize, e.g. selected list rows and menu items.
- `backgroundMuted` — Recessed or secondary areas that sit quietly behind content, e.g. page headers, code blocks, and sidebars.
- `backgroundInverted` — An opposite-scheme background, mainly for tooltips, toasts, and similar small floating elements.
- `surface` — Raised containers that sit on `background`: cards, modals, dropdowns.
- `overlay` — The area outside of dialogs, modals, and drawers, dimming the page behind them.

### Text

Used for `color` — text, and icons that should match it.

- `text` — The default text color, for body copy and headings.
- `textMuted` — Secondary text: placeholders, metadata, disabled and empty states, captions.
- `textInverted` — Text on `backgroundInverted`.

### Border

Used for `borderColor` — outlines, dividers, and separators.

- `border` — The default color for dividers and outlines of containers and inputs.
- `borderHighlight` — Emphasized borders, e.g. hovered inputs and cards.
- `borderMuted` — De-emphasized separators that only need to hint at structure.
- `borderInverted` — Borders on `backgroundInverted`.

## Common Pairings

Some roles are designed with each other in mind. Using them together is a
good way to keep contrast readable in both schemes:

- **`primary` + `onPrimary`** — filled buttons, badges, and other elements in
  your brand color.
- **`background` or `surface` + `text` / `textMuted`** — most of your
  content.
- **`backgroundInverted` + `textInverted` + `borderInverted`** — tooltips,
  toasts, and other opposite-scheme elements.
- **`surface` + `overlay`** — dialogs and drawers: the panel itself on
  `surface`, and the dimmed page around it on `overlay`.

For softer tints of any role — a light error banner, a subtle hover state —
see [`colorWithFade` and `colorWithOpacity`](/foundations/colors/utilities).
