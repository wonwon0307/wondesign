# Shortkey

`useShortkey` calls `callback` when the user presses a shortkey, like `Mod+K`.
`useShortkeyDisplay` gives you what you need to show that shortkey: its keys
for the user's platform, the `aria-label` value for screen readers, and the
`aria-keyshortcuts` value.

---

## Usage

```tsx
import { useState } from "react";
import {
  useShortkey,
  useShortkeyDisplay,
} from "@wondesign/key-events/shortkey";

const SEARCH_SHORTKEY = "Mod+K";

export function SearchButton() {
  const [isOpen, setIsOpen] = useState(false);
  useShortkey(SEARCH_SHORTKEY, () => setIsOpen((open) => !open));
  const display = useShortkeyDisplay(SEARCH_SHORTKEY);

  return (
    <button
      aria-keyshortcuts={display?.keyShortcuts}
      onClick={() => setIsOpen(true)}
    >
      Search <kbd aria-label={display?.label}>{display?.keys.join(" ")}</kbd>
    </button>
  );
}
```

- 📌 Pass the same constant, like `SEARCH_SHORTKEY`, to both hooks. Then the
  keys you show always match the keys that work, even after you change the
  shortkey.
- 📌 `useShortkeyDisplay` doesn't listen for key presses, so you can call it
  as often as you like, for example once in a button and again in its tooltip.
- 📌 With `label` as the keys' `aria-label`, screen readers read them by
  name, like "Command K", instead of reading out the symbols.
- 📌 To show the keys ready-styled, pass the same shortkey to
  [KeyboardGroup](/components/code/keyboard-group).

**Listening**:

- 📌 Listens on the whole page, wherever focus is.
- 📌 Shortkeys without Ctrl or ⌘ — like `/` or `Shift+S` — **don't fire while
  the user is typing** in an input, textarea, select or editable element.
- 📌 Holding a shortkey down calls `callback` once, not on every repeat.
- 📌 A matched shortkey replaces whatever the browser would do for it.

## Writing Shortkeys

A shortkey is up to two modifiers and a key, joined with `+`: `"K"`, `"Mod+K"`
or `"Mod+Shift+K"`. The order of the modifiers doesn't matter, but they must
match exactly — `Mod+K` doesn't fire when Shift is also held.

**Modifiers** — names on the same line mean the same thing:

- 🔵 `Mod` — ⌘ on Apple devices, Ctrl everywhere else
- 🔵 `Ctrl`, `Control`
- 🔵 `Alt`, `Opt`, `Option`
- 🔵 `Shift`
- 🔵 `Meta`, `Cmd`, `Command`, `Win`, `Windows`

**Keys**:

- 🟣 Letters `A` to `Z`, always written in uppercase. The case only matters
  when writing the shortkey: `Mod+K` fires when the user presses Mod and the K
  key, with no Shift needed, and whether Caps Lock is on doesn't matter.
- 🟣 Digits `0` to `9`
- 🟣 Symbols `` ` `` `-` `=` `[` `]` `\` `;` `'` `,` `.` `/`

`useShortkeyDisplay` also accepts `Enter`, `Return`, `Escape`, `Tab`, `Space`,
`CapsLock`, `Backspace`, `Delete`, the arrows `↑` `↓` `←` `→` and `F1` to
`F12` as the key, so you can show them. `useShortkey` doesn't bind them.

## API

Import the hooks, their types and the shortkey types from
`@wondesign/key-events/shortkey`.

### useShortkey

Listens for a shortkey. `key` and `callback` are required, while `options`
and everything in it can be left out:

```ts
interface ShortkeyOptions {
  // whether the hook is listening. defaults to `true`.
  // for example, turn it off while the feature it opens is unavailable.
  enabled?: boolean;
}

function useShortkey(
  // the shortkey to listen for, like `"Mod+K"`.
  // pass `null` to turn the hook off.
  key: BindableShortkey | null,
  // called when the shortkey is pressed.
  callback: () => void,
  options?: ShortkeyOptions,
): void;
```

### useShortkeyDisplay

Shows a shortkey, like in a button, a menu or a tooltip:

```ts
interface ShortkeyDisplay {
  // the keys as the user's platform writes them,
  // like `["⌘", "K"]` on a Mac and `["Ctrl", "K"]` elsewhere.
  keys: string[];
  // the value for the `aria-label` attribute,
  // the key names for screen readers, like `"Command K"`.
  label: string;
  // the value for the `aria-keyshortcuts` attribute, like `"Meta+K"`.
  keyShortcuts: string;
}

function useShortkeyDisplay(
  // the shortkey to show, like `"Mod+K"`.
  // pass `null` to show nothing.
  shortkey: Shortkey | null,
): ShortkeyDisplay | undefined;
```

It returns `undefined` when `shortkey` is `null`. Modifiers are listed in the
order each platform's users expect, whatever order you write them in — see
[KeyboardGroup](/components/code/keyboard-group#writing-shortkeys) for the
symbols and names on each platform.

Modifiers look different on each platform, so for a shortkey with modifiers,
**it returns `undefined` on the server and during hydration**, and fills in
once the page is running in the browser. A single key, like `K`, is returned
right away.

## Watch Out

- ⚠️ **Use `Mod` for cross-platform shortkeys**: `Ctrl` always means the
  Control key, on a Mac too, where users expect ⌘. Write `Mod+K`, not
  `Ctrl+K`, unless you really mean Control.
- ⚠️ **Write the unshifted symbol**: To bind `?`, write `Shift+/` — the key
  it's on. `?` itself is an invalid key.
- ⚠️ **Browser shortcuts are replaced**: Binding `Mod+S`, `Mod+F` or `Mod+P`
  **stops the browser from saving, finding or printing**. It's not
  recommended to turn a browser shortcut into a different feature — only do
  so if you really know what you're doing.
- ⚠️ **Shortkeys from outside your code**: TypeScript checks shortkeys you
  write, but not ones read at runtime, like from user settings. In
  `useShortkey`, an invalid one **does nothing**, apart from a warning in the
  console. `useShortkeyDisplay` **shows what it can, with no warning**: unknown
  modifiers are left out, and an unknown key is shown as written.
- ⚠️ **Avoid `Ctrl+Alt` shortkeys**: On Windows, the AltGr key counts as
  Ctrl+Alt, and many keyboards type characters with it — like `ą` on Polish
  or `@` on German keyboards. Binding `Ctrl+Alt+A` **stops Polish users from
  typing `ą`**, even inside inputs.

## Known Issues

- 🐞 **Every matching hook fires**: When more than one enabled `useShortkey`
  listens for the same shortkey, **one press calls every `callback`**. Make
  sure only one is enabled at a time, using `enabled` or `null`.
- 🐞 **Typing in web components**: Shortkeys without Ctrl or ⌘ **still fire
  while the user types** in an input inside a web component.
- 🐞 **Keys are matched by position**: Shortkeys follow where a key sits on a
  US QWERTY keyboard, not what's printed on it. On a French AZERTY keyboard,
  `Mod+Z` fires from the key labelled W. Support for
  [layout-aware shortkeys](/foundations/key-events/overview#upcoming-features)
  is planned.
